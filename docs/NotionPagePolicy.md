# 노션 페이지 생성 정책

본 문서는 본 저장소 (LyraSkeleton) 의 강의 / 분석 문서를 노션 페이지로 옮길 때 따르는 양식 / 구조 / 절차 규칙을 정리한다.

Claude Code 가 노션 페이지를 생성 / 수정하기 전 반드시 본 문서를 확인한다. 사용자의 그 자리 요청이 본 정책과 충돌하면 사용자의 요청을 우선하되, **정책에서 벗어난 사실** 을 사용자에게 명시한다.

본 정책은 **Notion MCP 의 enhanced markdown** 을 사용하는 환경 (`<callout>`, `<table>`, `{toggle="true"}` 등) 을 기준으로 한다. Notion UI 의 일반 markdown import 경로는 별도 정책이 필요한 시점에 추가한다.

## 1. 목적

- 학생이 프로젝트를 실행하며 따라가는 강의 문서를 생성한다.
- 본 저장소의 분석 레퍼런스 (HTML, DeepReanalysis) 와 강의 본문을 섞지 않는다.
- 같은 생성 작업을 반복할 때 양식 / 구조가 변동하지 않도록 한다.

## 2. 생성 모드

| 모드 | 용도 | 페이지 단위 | 기본값 여부 |
|---|---|---|---|
| A. 단일 페이지 통합 | 사용자가 "한 페이지에 모든 Step" 을 명시한 경우 | Step 1 ~ 4.5 가 한 페이지 안 H1 토글 5개 | 본 정책의 기본값 |
| B. Step 별 하위 페이지 | 학생이 Step 별로 진입 / 검색 / 공유를 자주 한다고 판단되는 경우 | 강의 홈 페이지 + Step 별 자식 페이지 | 사용자 요청 시 |
| C. 심화 레퍼런스 분리 | Step 4.5 같은 분석 자료만 별도 페이지로 두는 경우 | 정규 강의 페이지 + 심화 레퍼런스 페이지 별도 | 사용자 요청 시 |

기본값은 모드 A. 사용자가 다른 모드를 명시하면 그 모드를 따른다. 모드별 차이는 본 정책의 각 절에서 명시한다.

### 2.1 모드 A 의 기본 구조

```text
[페이지 제목]
├ 상단 인덱스 콜아웃 (Step 구성, 한 줄 부제 포함)
├ # Step 1 {toggle="true"}
│   └ Step 본문 (5절 템플릿)
├ # Step 2 {toggle="true"}
├ # Step 3 {toggle="true"}
├ # Step 4 {toggle="true"}
└ # Step 4.5 {toggle="true"}
```

### 2.2 모드 B 의 기본 구조

```text
강의 홈 페이지
├ 페이지 본문: Step 별 mention / 부제 / 진입 안내
├ Step 1 (자식 페이지)
├ Step 2 (자식 페이지)
├ Step 3 (자식 페이지)
├ Step 4 (자식 페이지)
└ Step 4.5 (자식 페이지)
```

모드 B 의 페이지 간 링크는 노션 페이지 mention 으로 통일.

## 3. 원본 선택

노션 본문을 만들 때 어느 저장소 문서를 원본으로 삼는지 정한다. 한 노션 페이지의 본문 안에 톤이 다른 원본을 섞지 않는다.

| 노션 페이지 용도 | 원본 (필수) | 보조 참조 |
|---|---|---|
| 강의 본문 | `docs/Lectures/LectureStep*.md` | `docs/Step*/` (외부 링크), `docs/Step4.5_DeepReanalysis.md` (Step 4.5 한정) |
| 심화 레퍼런스 | `docs/Step4.5_DeepReanalysis.md` 또는 `docs/Research_UE_Asset_Analyze.md` | `docs/Step*/` HTML |
| Archive / 공개 안내 원문 | `docs/Announcements.md` | (없음) |

원칙:

- 강의 본문 페이지에는 `Announcements.md` 의 공개 안내 원문을 섞지 않는다.
- 강의 본문 페이지의 한 단락이 원본 마크다운의 한 단락과 1대1 대응이어야 한다. 임의 보강 / 생략은 금지.
- 사실 정정 (예: `GaitSettings` 의 Walking / Jogging) 은 모든 원본을 먼저 정정한 뒤에 옮긴다.

## 4. 페이지 단위 양식

### 4.1 H1 토글 제목은 짧게

- H1 토글 (`# Step N {toggle="true"}`) 의 제목은 `Step 1`, `Step 4.5` 처럼 식별자만.
- Step 의 상세 제목은 H1 토글을 펼친 직후의 **결과 콜아웃 헤더** 가 들고 있다 (5.1 절).

| 잘못된 예 | 올바른 예 |
|---|---|
| `# Step 1 - AnimationLayerInterface 기반 무기별 애니메이션 스위칭 {toggle="true"}` | `# Step 1 {toggle="true"}` |
| `# Step 4.5 - Start/Stop/Pivot 심화 분석 {toggle="true"}` | `# Step 4.5 {toggle="true"}` |

모드 B (Step 별 하위 페이지) 에서는 페이지 제목 자체에 상세 제목을 둔다 (예: 페이지 제목 = `Step 1 - Linked Anim Layer 와 무기별 애니메이션 전환`).

### 4.2 상단 인덱스 콜아웃

페이지 상단에는 **단 하나의 인덱스 콜아웃** 만 둔다.

권장 형식:

```text
<callout icon="📑">
	### Step 구성
	---
	- Step 1. Linked Anim Layer 와 무기별 애니메이션 전환
	- Step 2. Gait, Aim 입력, LocomotionSM
	- Step 3. 4 방향 로코모션과 Debug
	- Step 4. Start/Stop/Pivot, Distance Matching, Warping
	- Step 4.5. Step 4 자산 심화 분석
</callout>
```

- 식별자 (`Step N`) + 한 줄 부제 (Step 의 핵심 주제) 로 정보 밀도 확보.
- H1 토글 제목이 짧기 때문에 인덱스에서 부제가 없으면 학생이 "Step 3 이 뭐였지" 를 바로 알 수 없다.
- 한 단락 이상의 강의 전체 개요는 두지 않는다.

다음 콜아웃은 두지 않는다.

- "이 강의가 다루는 것" 같은 강의 전체 개요 콜아웃 (Step 본문이 같은 페이지 안에 모두 있으므로 중복).
- "읽는 방법" / "사용 안내" 콜아웃 (페이지 구조가 자명).

## 5. Step 본문 구조

각 Step 의 H1 토글 안 콘텐츠 골격.

```text
# Step N {toggle="true"}
	<callout icon="🎯" color="blue_bg">
		### [결과] <Step 의 상세 제목>
		---
		<Step 의 한 두 문장 요약 - "이번 Step 에서 만드는 것">

		**결과**
		- <결과 1>
		- <결과 2>
		- <결과 3>
	</callout>

	## 0. 이번 Step 의 신규 / 변경 자산 {toggle="true"}
		<table>...</table>

	## 1. <중심 기능 1> {toggle="true"}
		...

	## 2. <중심 기능 N> {toggle="true"}
		...

	## N. 꼭 알아야 할 기능 {toggle="true"}
		### <기능 A>
		### <기능 B>
		### <기능 C>

	## M. <학습 포인트 / 데이터 흐름 한 장 / 다음 단계 후보> {toggle="true"}
		...
```

### 5.1 결과 콜아웃 통합

이전의 두 콜아웃 ("이번 Step 에서 만드는 것" + "결과물 한눈에") 을 **하나로 통합** 한다.

- 콜아웃 헤더 H3 (`###`) 자리: `[결과] <Step 의 상세 제목>` 형식. **텍스트 라벨** `[결과]` 가 색깔만으로 의미를 전달하는 것을 막는다.
- 첫 단락: 이번 Step 의 의도 / 결과를 한 두 문장으로.
- `---` 구분선.
- `**결과**` 굵은 글씨 + 불릿 리스트.

권장 아이콘 / 색깔: `icon="🎯"` `color="blue_bg"`.

심화 자료 (예: Step 4.5) 는 `icon="🔬"` `color="purple_bg"` 로 차별화 가능. 헤더 라벨은 `[심화]`.

### 5.2 H1 토글 직후 별도 H2 제목 두지 않음

H1 토글 제목을 짧게 (`Step 1`) 둔 대신, 펼쳤을 때 **결과 콜아웃 헤더** 가 Step 의 상세 제목 역할. 별도 H2 / H3 으로 제목을 또 적지 않는다.

예외 (모드 B): Step 별 하위 페이지 모드에서는 페이지 제목 자체가 상세 제목을 들고 있으므로 결과 콜아웃 헤더는 `[결과]` 라벨만 두어도 된다.

### 5.3 "꼭 알아야 할 기능" 카테고리 정책

원칙: 같은 카테고리의 기능은 **하나의 H2 토글** 안에 H3 (`### `) 으로 묶는다.

```text
## N. 꼭 알아야 할 기능 {toggle="true"}
	### PropertyAccess
	(본문 + 표 + 코드 블록)

	### Inertialization
	(본문 + 표 + 코드 블록)

	### Enhanced Input
	(본문 + 표 + 코드 블록)
```

기능 수 임계값:

- **3 개 이하**: 단일 "꼭 알아야 할 기능" 토글 안에 모두 묶기.
- **4 개**: 묶거나 분리하거나 본문 길이에 따라.
- **5 개 이상**: 주제별로 H2 토글을 분리한다. 같은 카테고리임을 보이기 위해 모든 H2 토글의 접두어를 `꼭 알아야 할 기능 - ` 로 시작한다.

예 (Step 4, 7 기능 분리):

```text
## N. 꼭 알아야 할 기능 - Distance Matching {toggle="true"}
	### Sequence Player vs Sequence Evaluator
	### Distance Matching 4 함수
	### OnInit / OnUpdate 쌍 구조

## N+1. 꼭 알아야 할 기능 - Warping / 전이 {toggle="true"}
	### Orientation Warping
	### Stride Warping
	### PivotSM
	### AnimNotify 기반 전이 트리거
```

원본 마크다운에서 각 기능 안의 서브 섹션 (예: 5.1 / 5.2 / 5.3) 은 H4 (`#### `) 로 한 단계 내려서 유지한다.

### 5.4 마무리 섹션

원본 마크다운에 다음 섹션이 있으면 그대로 옮긴다.

- 학습 포인트 정리
- 데이터 흐름 한 장
- 다음 단계 후보 (구체적 작업 항목 리스트)

다음 섹션은 **제거** 한다.

- "다음 Step 부터 이 슬롯들이 채워지면서..." 같은 마지막 안내 콜아웃 (통합 페이지 안에 다음 Step 이 같이 있으므로 중복).
- "이번 Step 의 빈 슬롯 (다음 Step 에서 채울 영역)" 토글 섹션 전체 (다음 Step 안내 성격).

원본 마크다운에 위 두 섹션이 있어도 모드 A 의 노션 페이지에서는 옮기지 않는다. 모드 B (Step 별 하위 페이지) 에서는 다음 Step 으로 이어주는 안내가 학습 흐름상 유용하므로 보존을 고려한다.

### 5.5 원본에 없는 블록 임의 생성 금지

다음 블록은 **원본 마크다운에 있을 때만** 옮긴다. 노션 페이지를 위해 임의 생성하지 않는다.

- "실행해서 확인하기" 안내
- "에디터에서 열어볼 위치" 안내
- "직접 확인 과제" / "확인 질문"
- "자주 헷갈리는 지점"
- 시각 자료 (Blueprint / AnimGraph 캡처 등)

원본 LectureStepN.md 에 이런 블록을 추가하는 것은 노션 생성과 별개 작업이며, 별도 사용자 결정이 필요하다. 본 정책의 노션 생성 절차는 원본 마크다운에 충실한다.

## 6. 노션 양식 규칙

### 6.1 토글 구분

| 레벨 | 용도 | 토글 여부 |
|---|---|---|
| H1 (`#`) | Step 전체 구분. 제목은 `Step N` 으로 짧게. | **반드시 토글** |
| H2 (`##`) | Step 안의 큰 섹션 (0번 신규 자산, 1번 중심 기능, ...) | **반드시 토글** |
| H3 (`###`) | H2 안의 서브 섹션 / 카테고리 토글 안의 개별 항목 | 토글 아님 |
| H4 (`####`) | H3 안의 더 작은 서브 (필요할 때만) | 토글 아님 |

토글의 자식은 **tab indent** 필수. H1 토글의 자식은 tab 1개, H1 토글 안의 H2 토글 자식은 tab 2개.

### 6.2 콜아웃

색상 / 아이콘 권장표:

| 용도 | 헤더 라벨 | icon | color |
|---|---|---|---|
| Step 결과 요약 (Step 본문 시작) | `[결과]` | 🎯 | blue_bg |
| 핵심 / 주의 강조 (본문 중간) | `[핵심]` 또는 `[주의]` | ⭐ | yellow_bg |
| 학습 가치 / 한 줄 요약 (본문 중간) | `[참고]` | 📝 | green_bg |
| 경고 (잘못 쓰면 깨짐) | `[경고]` | ⚠ | red_bg |
| 심화 / 특수 자료 (Step 4.5 같은) | `[심화]` | 🔬 | purple_bg |
| 페이지 상단 인덱스 | (라벨 없음, "Step 구성" 같은 헤더) | 📑 | (색 없음) |

**접근성 원칙: 색상만으로 의미를 전달하지 않는다.** 콜아웃 헤더에 텍스트 라벨 (`[결과]`, `[주의]`, `[심화]` 등) 을 둔다. 색맹 사용자 / 모바일 다크 모드 / 흑백 인쇄에서도 의미가 전달되도록.

본문 중간에 색깔 콜아웃을 남발하지 않는다. 한 섹션에 1개 이내가 자연스럽다.

### 6.3 표

- 기본: `<table header-row="true">`
- 3 컬럼 이상 + 긴 셀: `<table header-row="true" fit-page-width="true">`
- 셀 안에서 백틱 인라인 코드 (`` `BP_LsCharacter` ``), `**굵게**` 만 사용. HTML 태그 (`<strong>`, `<br>`, `<u>`) 금지.

### 6.4 큰 표 / 긴 원문은 추가로 한 번 더 접기

H2 토글 안에서도 다음 항목은 추가로 H3 `<details>` 또는 별도 카테고리 토글 등으로 **한 번 더 접는다**. H2 펼치는 순간 한 화면이 표로 가득 차는 것을 막는다.

- LocomotionSM 13 전이 rule_nodes 표 (Step 4.5)
- 출처 매트릭스 / 검증 근거 표
- 긴 저자 코멘트 원문 (3 단락 초과)
- Monolith 응답 한계 설명
- 노드 수 전수 표 (한 표가 화면 한 폭을 넘는 경우)

### 6.5 코드 블록

- 언어 표기는 `text` (노션이 `plain text` 로 자동 변환). 또는 알려진 언어 (`cpp`, `mermaid`).
- 코드 블록 안의 한국어 / 화살표 / 박스 문자는 원본 그대로.
- 한 코드 블록이 한 화면을 넘어가면 가독성을 위해 분할 또는 일부를 토글에 넣는다.

### 6.6 번호 매김

**기본은 ASCII 숫자 + 마침표.**

```text
## 0. 이번 Step 의 신규 자산
## 1. 중심 기능
## 2. 꼭 알아야 할 기능
## 3. 학습 포인트
```

Keycap 이모지 (`0️⃣`, `1️⃣`, ..., `🔟`) 는 **사용자가 명시적으로 요청한 경우에만** 사용한다. 일반 번호 매김에는 사용하지 않는다.

이유:

- 11 이상부터 keycap 규칙이 깨진다 (두 자릿수 keycap 이 일반적이지 않음).
- 검색 / 복사 / 목차 일관성을 해친다.
- `CLAUDE.md` 의 본문 특수문자 정책과 예외 관계가 복잡해진다.
- 페이지 제목 / 검색 결과 / 복사한 텍스트에 이모지가 섞인다.

### 6.7 인용 (저자 코멘트)

- 한 줄 인용: `> 인용문`
- 여러 단락 인용은 단락 사이에 빈 줄 (단순 `>` 만 있는 줄 두지 않기). 단락마다 `> ` 로 다시 시작한다. 노션은 newline 만 있으면 인용이 깨진다.

### 6.8 링크 변환

원본 마크다운의 상대 링크 (`./LectureStepN.md` 등) 는 노션에서 그대로 의미가 없다. 모드별로 변환한다.

| 원본 링크 형식 | 모드 A (단일 페이지) | 모드 B (Step 별 페이지) |
|---|---|---|
| `[Step 1 ...](./LectureStep1.md)` | 같은 페이지 안내 문장으로 풀어 쓰기 (예: "위 Step 1 의 ... 참조") | 노션 페이지 mention 으로 교체 |
| `./Step1.md` 같은 깨진 원본 링크 | 옮기기 전에 원본 마크다운에서 정정 (`./LectureStep1.md` 로) | 동일 |
| 외부 레퍼런스 (`docs/Step1/index.html`) | GitHub Pages URL 또는 저장소 raw URL 중 하나로 통일 | 동일 |

### 6.9 본문 특수문자

- 본 저장소의 마크다운 / HTML 본문 정책 (`CLAUDE.md`) 은 노션 페이지 본문에도 동일하게 적용한다.
- 예외: 노션 고유 UI 요소 (콜아웃 아이콘, 페이지 아이콘) 는 노션이 그래픽 글리프로 요구하는 자리에서만 허용. 본문 산문 안에는 등장하지 않는다.
- 한국어 본문 / 자산 식별자 톤은 원본 LectureStepN.md 그대로 보존.

### 6.10 시각 자료

- 강의 페이지에는 가능하면 다이어그램 / 캡처 한 장 이상 권장. 다만 강제는 아니다.
- 저장소에 이미지가 있으면 노션에 같이 옮긴다.
- 이미지가 없으면 Mermaid 다이어그램 또는 ASCII 박스 다이어그램 (이미 원본에 있는 형태) 으로 대체.
- **노션 페이지를 위해 임의로 새 이미지를 생성하지 않는다.** 원본에 없는 시각 자료가 필요하다면 별도 사용자 결정이 필요하다.

## 7. 페이지 생성 절차

새 노션 페이지를 만들거나 기존 페이지를 큰 폭으로 다시 채울 때:

1. **본 정책 문서를 먼저 읽는다.**
2. `notion://docs/enhanced-markdown-spec` MCP 리소스로 노션 마크다운 스펙 최신본을 fetch.
3. 다음이 명확하지 않으면 사용자에게 확인 (`AskUserQuestion`):
   - 부모 페이지 위치
   - 페이지 제목 / 아이콘
   - 생성 모드 (A / B / C)
   - 원본 마크다운 (어느 `LectureStepN.md` / `Step*.md`)
4. **샘플 Step 1 개를 먼저 생성** 해 사용자에게 양식 확인 (특히 본 정책 첫 적용 또는 양식이 바뀐 직후).
5. 인트로 + 첫 Step → 페이지 생성 액션 (Claude MCP: `notion-create-pages`).
6. 나머지 Step → 페이지 update 액션 (Claude MCP: `notion-update-page`, `insert_content`, `position={"type":"end"}`) 으로 차례로 append.
7. 모든 append 후 페이지 fetch 액션 (Claude MCP: `notion-fetch`) 으로 구조 점검 (8 절 체크리스트).
8. 사용자에게 결과 URL + 구조 요약 + 정책에서 벗어난 항목 (있다면) 명시.

원칙과 도구명 분리:

- **원칙**: 부모 / 제목 / 아이콘 / 모드 / 원본을 확정 → 샘플 검증 → 본 생성 → 사후 fetch 검증.
- **Claude MCP 도구명 (참고)**: `notion-create-pages`, `notion-update-page` (`insert_content` / `replace_content` / `update_properties`), `notion-fetch`, `notion-search`.

다른 환경 (Codex 등) 에서는 동등 액션으로 대체한다. 원칙은 환경 비종속이다.

## 8. 사후 검증 체크리스트

생성 / 수정 후 fetch 로 다음을 점검한다.

### 8.1 구조
- 페이지 제목 / 아이콘이 의도대로
- 모드 A: H1 토글 수 = Step 수
- 각 H1 토글 안 첫 콜아웃에 `[결과]` 라벨 + 상세 제목 + 결과 불릿
- 각 H2 토글이 정확히 모두 토글 (`{toggle="true"}`)
- H3 / H4 가 토글이 아닌 일반 헤딩

### 8.2 콘텐츠
- 모든 표가 `header-row="true"` 적용
- 큰 표가 `fit-page-width="true"` 또는 추가 토글로 접힘
- 코드 블록의 한국어 / 박스 문자가 깨지지 않음
- 인용문이 여러 단락에서도 한 인용으로 유지됨
- 원본에 없는 보강 블록을 임의 생성하지 않음

### 8.3 링크 / 사실 일관성
- 원본 마크다운의 `./LectureStepN.md` 같은 상대 링크가 본 정책 6.8 절에 따라 변환됨
- 강의 본문과 Announcement 원문이 섞이지 않음
- 사실 정정 항목 (예: `GaitSettings` 의 Walking / Jogging, MaxAccel = 500) 이 모든 본문 위치에서 일관되게 반영됨

### 8.4 학습 자료 품질
- 각 Step 의 정보 밀도가 균등 (한 Step 만 비대하지 않음)
- H2 토글 펼쳤을 때 한 화면이 표로 가득 차지 않음
- 모바일에서 큰 표가 가로 스크롤 또는 fit-page-width 로 읽힘
- 색상 콜아웃에 텍스트 라벨이 함께 있음 (접근성)

### 8.5 (선택) 실제 페이지 열어보기
- 생성된 노션 URL 을 실제로 열어 페이지 최상단 → 마지막 Step 까지 스크롤로 검수
- 사이드바 / 검색 / 모바일 뷰에서 단순 식별 가능 여부 확인
