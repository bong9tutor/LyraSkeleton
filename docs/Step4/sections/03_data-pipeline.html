ABP_Base: 가속도와 회전까지 모으는 6 단 파이프라인

섹션 02 의 13 개 전이 룰은 전부 변수를 읽는다. 그 변수를 매 프레임 만드는 곳이 ABP_Base 의 BlueprintThreadSafeUpdateAnimation 이다. Step 3 의 5 단 파이프라인이 Step 4 에서 6 단으로 늘고, 변수는 8 개에서 24 개로 불었다. 이 섹션은 새로 들어온 가속도·회전·Gait 전이 데이터가 어떻게 수집되는지 노드 단위로 따라간다.

ABP_Base 변수: 8 → 24

Step 3 의 8 개 위에 16 개가 늘었다. 새 변수는 카테고리로 깔끔하게 묶인다 - 가속도, 회전(Yaw), Gait 전이, 위치 변화, 가속도 기반 방향.

1 단계: BTSUA 가 5 단에서 6 단으로

BlueprintThreadSafeUpdateAnimation(DeltaTime) 의 exec 체인은 Step 3 대비 호출 순서가 바뀌고 SetAccelerationData / SetCharacterStates 두 단계가 들어왔다.

BlueprintThreadSafeUpdateAnimation (exec 순서, 9 노드) 
FunctionEntry
  → SetLocationData(DeltaTime)              # WorldLocation, DeltaLocation
  → SetVelocityData                        # CharacterVelocity / 2D
  → SetAccelerationData                    # Step4: Acceleration / 2D, bIsAccelerating
  → SetRotationData(DeltaTime, LeanInterpScale=6)  # Yaw 계열, LeanAngle
  → UpdateOrientationData                  # 속도방향 + 가속도방향
  → SetCharacterStates                     # Step4: Gait 전이

함수 시그니처도 손봤다. Step 3 에서 입력 핀이 없던 SetLocationData / SetRotationData 가 이제 DeltaTime 을 받는다 - "이번 프레임 경과 시간" 으로 변화율(DeltaLocation, 각속도)을 계산해야 하기 때문이다.

2 단계: SetLocationData - 위치와 이동 거리

저자 설명: "캐릭터의 현재 위치 정보를 각 변수에 설정". 10 노드, exec 순서:

SetLocationData 
FunctionEntry
  → Set LastWorld Location   # 갱신 전에 직전 WorldLocation 을 백업
  → Set WorldLocation       # PropertyAccess 로 현재 위치
  → Set DeltaLocation       # VectorLengthXY(WorldLocation - LastWorld Location)

DeltaLocation 은 이번 프레임에 실제로 이동한 평면 거리다. "직전값을 먼저 백업 → 현재값 갱신 → 둘의 차" 라는 패턴이 Step 4 전반에 반복된다(아래 Yaw, Gait 도 같은 모양).

3 단계: SetAccelerationData - 입력 의도 읽기

신규 함수. 저자 설명: "캐릭터의 가속 관련 값을 설정." 11 노드:

SetAccelerationData 
FunctionEntry
  → Set Acceleration      # PropertyAccess (CharacterMovement 의 가속도)
  → Set Acceleration2D    # Acceleration * (1,1,0) 으로 Z 제거
  → Set bIsAccelerating   # NOT NearlyEqual( VectorLengthXY(Acceleration2D), 0 )
i
왜 속도(Velocity)가 아니라 가속도(Acceleration)인가 Velocity 는 캐릭터가 실제로 움직이는 방향이고, Acceleration 은 플레이어가 입력한 방향이다. 둘은 보통 같지만, 출발 순간(아직 안 움직임)·정지 순간(입력 뗐는데 관성)·급선회(입력은 새 방향, 속도는 옛 방향)에서 갈라진다. 그래서 bIsAccelerating(입력 있나?)이 Idle↔Start↔Stop 전이의 핵심이고, 속도와 가속도의 각도 차가 Pivot 감지의 핵심이다 (섹션 02 의 전이 룰이 정확히 이 두 값을 비교했다).

4 단계: SetRotationData - 회전과 각속도

저자 설명: "캐릭터의 현재 회전 정보를 각 변수에 설정". Step 3 의 3 노드가 Step 4 에서 20 노드로 커졌다. 회전 원시값(WorldRotation) 외에 Yaw 변화량을 계산한다:

SetRotationData - 회전 데이터 부분 
FunctionEntry
  → Set WorldRotation    # PropertyAccess
  → Set LastFrameYaw     # 직전 CurrentYaw 백업
  → Set CurrentYaw       # WorldRotation 의 Yaw
  → Set DeltaYaw         # CurrentYaw - LastFrameYaw (이번 프레임 회전량)
  → Set LeanAngle        # DeltaYaw + DeltaTime + LeanInterpScale 로 산출 → 섹션 06

DeltaYaw 까지가 "회전 데이터" 이고, 그 뒤 LeanAngle 산출(각속도 환산 · 방향별 부호 반전 · 한계 클램프)도 이 함수에 있다. 다만 이 LeanAngle 을 받을 BS_Lean BlendSpace 합성은 아직 미완이다 - 준비된 데이터와 비어 있는 합성의 구분은 섹션 06 에서 따로 다룬다.

5 단계: UpdateOrientationData - 방향을 두 갈래로

Step 3 에서 이 함수는 5 노드로 LocomotionAngle 하나만 만들었다. Step 4 는 19 노드로 커지며 속도 기반과 가속도 기반 두 가지 방향을 모두 계산한다.

UpdateOrientationData (exec) 
FunctionEntry
  → Set LastLocomotionDirection   # 직전 LocomotionDirection 백업 (전이 ② 가 읽음)
  → Set LocomotionAngle           # CalculateDirection(CharacterVelocity2D, WorldRotation)
  → Set AccelerationLocomotionAngle  # CalculateDirection(Acceleration2D, WorldRotation)
  → CalculateLocomotionDirectionWithDeadzone(Angle=LocomotionAngle, ...)
  → Set LocomotionDirection           # 속도 기반 4 방향
  → CalculateLocomotionDirectionWithDeadzone(Angle=AccelerationLocomotionAngle, ...)
  → Set AccelerationLocomotionDirection  # 가속도(입력) 기반 4 방향

CalculateLocomotionDirectionWithDeadzone 는 Step 3 의 CalculateLocomotionDirection 을 이름만 바꾼 함수다(72 노드, 히스테리시스+DeadZone 로직 동일). 두 호출 노드의 입력 핀을 보면 임계값은 Step 3 과 완전히 동일하다:

호출입력 각도Fwd / Bwd / DeadZone출력
① 속도← LocomotionAngle±50 / ±130 / 20→ LocomotionDirection
② 가속도← AccelerationLocomotionAngle±50 / ±130 / 20→ AccelerationLocomotionDirection

핀 기본값: ForwardMin/Max = -50/50, BackwardMin/Max = -130/130, DeadZone = 20 (두 호출 노드 모두 동일). CurrentDirection 핀은 각각 LocomotionDirection / AccelerationLocomotionDirection 에 연결(히스테리시스 피드백).

6 단계: SetCharacterStates - Gait 전이 감지

신규 함수. 저자 설명: "캐릭터의 이동, 무기 등 상태 관련 값을 설정". 9 노드. 여기서도 "직전값 백업 → 현재값 → 비교" 패턴이다:

SetCharacterStates + OnGaitChanged 연동 
# [EventGraph] BP_LsCharacter 가 보낸 메시지를 받음
Event OnGaitChanged  # 코멘트: "캐릭터에서 이동상태 변경시 호출됨"
  → Set IncommingGait

# [SetCharacterStates] 매 프레임 BTSUA 안에서
FunctionEntry
  → Set LastGait        # 직전 CurrentGait 백업
  → Set CurrentGait     # IncommingGait 를 반영
  → Set bIsGaitChanged  # NotEqual(CurrentGait, LastGait)

BP_LsCharacter 가 우클릭(Aim) 입력으로 Gait 를 바꾸면 OnGaitChanged 메시지를 쏘고(Step 2 에서 분석된 BPI 채널), ABP_Base 의 EventGraph 가 그것을 받아 IncommingGait 에 적어 둔다. 그러면 다음 프레임 SetCharacterStates 가 그 값을 CurrentGait 으로 확정하면서 bIsGaitChanged 를 세운다 - 이 bool 이 섹션 02 의 전이 Start → Cycle ③ 을 트리거한다(출발 중 Gait 가 바뀌면 Start 를 건너뜀).

OnInitPivotState - Pivot 진입 순간을 박제하다

OnInitPivotState 는 신규 함수로, LocomotionSM 의 Pivot 상태에 진입하는 순간 한 번 호출되는 콜백이다. 6 노드, 하는 일은 단 하나:

OnInitPivotState 
FunctionEntry
  → Set PivotAcceleration2D   # = Acceleration2D (진입 순간의 입력 방향)
  → Return
"
BP 내 저자 코멘트 (원문 그대로) Set PivotAcceleration2D 노드: "Pivot 상태에서 다른 상태로 전환 조건에 사용." - 피벗에 들어선 그 순간의 입력 방향을 얼려 두고, 이후 캐릭터의 속도가 그 방향으로 정렬되면 피벗이 끝났다고 본다(섹션 02 의 전이 Pivot → Cycle ① 이 PivotAcceleration2D 와 CharacterVelocity2D 의 정렬을 검사).
