ABP_Layers: 전이 동작과 발 미끄러짐 제거

섹션 02 의 5 상태가 ALI_Animation 레이어를 부르면, 그 레이어의 실제 구현이 ABP_Layers 에 있다. Step 4 는 여기에 Stop/Start/Pivot 세 레이어의 OnInit/OnUpdate 6 콜백을 추가했다. 공통 도구는 Sequence Evaluator 와 Distance Matching - 애니메이션의 발을 캐릭터의 실제 이동 거리에 묶어 미끄러짐을 없앤다. 레이어 그래프 자체(Warping 포함)는 섹션 05 에서 다룬다.

ABP_Layers 변수: 3 → 12

Step 3 의 3 개에서 9 개가 늘었다. 6 개는 Step 3 의 S_DirectionalAnims(4 방향 시퀀스 묶음)를 그대로 재사용한 전이 애님 묶음이고, 3 개는 Stride Warping 파라미터다.

i
Step 3 의 S_DirectionalAnims 가 4 번 재사용됐다 Step 3 은 "한 Gait 의 4 방향 시퀀스" 를 S_DirectionalAnims 구조체로 묶었다. Step 4 는 그 구조체를 손대지 않고 Stop/Start/Pivot 묶음에 그대로 다시 썼다 - Walk/Jog x Cycle/Stop/Start/Pivot = 8 개 변수가 전부 같은 타입이다. 데이터 모델 하나를 잘 만들면 새 동작은 "변수 추가" 로 끝난다. ABP_Layers 의 의존 애니메이션도 MM_Unarmed_{Walk/Jog}_{Fwd/Bwd/Left/Right}_{Start/Stop/Pivot} 으로 채워져, Step 3 에서 비어 있던 방향 묶음이 실제 애님으로 들어찼다. 단, Pivot 묶음은 선택 방향과 에셋명이 반대로 보이는 매핑을 가진다: Forward → *_Bwd_Pivot, Backward → *_Fwd_Pivot, Right → *_Left_Pivot, Left → *_Right_Pivot. 피벗은 현재 진행 방향과 새 가속 방향의 관계로 고르는 전이 동작이라, 이 기본값을 보수할 때 이름만 보고 되돌리면 안 된다.

핵심 도구: Sequence Player vs Sequence Evaluator

Step 4 의 6 개 콜백을 이해하려면 두 노드의 차이를 먼저 봐야 한다. Idle/Cycle 과 Stop/Start/Pivot 이 다른 노드를 쓴다 - 이게 Step 4 레이어 설계의 갈림길이다.

측면Sequence Player (Idle / Cycle)Sequence Evaluator (Stop / Start / Pivot)
시간 진행스스로 흐름 (재생 속도대로 자동)안 흐름 - Explicit Time 을 외부가 지정
제어 방식"틀어 놓으면 알아서" "몇 초 지점을 보여줄지" 를 매 프레임 계산
Step 4 용도지속 동작 (가만히 / 순항)이동 거리에 동기화해야 하는 전이 동작
콜백OnUpdate 만 (OnIdleUpdate / OnCycleUpdate)OnInit + OnUpdate (진입 시 1 회 + 매 프레임)

그래서 신규 6 콜백은 모두 OnInit(진입 시 1 회) + OnUpdate(매 프레임) 쌍이다. OnInit 은 "무엇을 재생할지"(시퀀스 선택)를, OnUpdate 는 "어디를 재생할지"(시간 위치)를 책임진다 - 저자가 OnUpdatePivotAnims 의 Comment 노드에 그대로 적어 둔 분담이다.

Distance Matching 이란 무엇인가

Step 4 의 전이 동작은 전부 같은 문제를 푼다: 애니메이션의 발과 캐릭터의 실제 위치가 어긋나면 미끄러진다. Stop 애니메이션이 1 초짜리인데 캐릭터가 0.6 초만에 멈추면, 남은 0.4 초 동안 발이 바닥을 긁는다. Distance Matching 은 시간이 아니라 거리로 애니메이션을 재생해 이걸 없앤다. 저자가 Distance Match to Target 노드에 적은 설명이 정확하다:

"
BP 내 저자 코멘트 (원문 그대로) - Distance Match to Target "목표 지점까지 남은 거리(Distance to Target)에 대응하는 정확한 프레임 위치로 재생 시간을 맞춰주는 함수입니다. 애니메이션에 거리 정보가 담긴 커브(Distance Curve)가 들어 있어야 하며, 이 커브를 역으로 조회해 '현재 남은 거리 = 커브상 어느 시간점인가'를 찾아 Sequence Evaluator의 Explicit Time을 설정합니다. 결과적으로 캐릭터의 실제 이동 거리와 애니메이션의 발 위치(루트 모션)가 정확히 동기화되어, 미끄러짐(foot sliding) 없이 정지, 시작 애니메이션을 정렬할 수 있습니다."

파트너 노드는 Predict Ground Movement Stop Location / ...Pivot Location 이다 - 캐릭터 무브먼트 컴포넌트의 마찰·감속 설정으로 "입력 없이 두면 어디서 멈출까(꺾일까)" 를 예측해, 그 남은 거리를 Distance Matching 에 먹인다.

Stop 레이어: OnInitStopAnims + OnUpdateStopAnims

가장 단순한 형태다:

Stop 레이어 흐름 
# [Stop 진입 1 회] OnInitStopAnims (17 노드)
Convert to Sequence Evaluator
  → Select[CurrentGait]( Select[Dir](WalkStopAnims), Select[Dir](JogStopAnims) )
  → Set Sequence            # Evaluator 에 방향·Gait 맞는 Stop 시퀀스 지정
  → Set Explicit Time = 0    # "정지 애니메이션을 처음부터 시작하기 위함"

# [Stop 매 프레임] OnUpdateStopAnims (27 노드)
Predict Ground Movement Stop Location   # 자연 감속 시 멈출 지점 예측
  → StopDistnace = VectorLengthXY(예측 오프셋)
  → Branch( StopDistnace > 0 )
       ├─ true  → Distance Match to Target  # 남은 거리 → 커브상 프레임
       └─ false → Advance Time             # 거리 0, 잔여 구간 자연 재생

저자가 OnUpdateStopAnims 의 Branch 위 Comment 노드에 두 갈래를 직접 설명해 뒀다 (원문 그대로): "True(거리가 남음): Distance Match to Target으로 남은 Stop Distance에 대응하는 프레임으로 시퀀스 시간을 정렬합니다. 정지 동작이 거리와 동기화되어 진행됩니다. / False(거리가 0 이하, 즉 사실상 정지 완료): Advance Time으로 평가기 시간을 일반 재생처럼 자연 진행시켜, 정지 애니메이션의 잔여 구간을 마저 재생합니다."

변수 이름 StopDistnace 의 철자(Distance 가 아님)는 저자의 실제 명명 그대로다.

Start 레이어: 거리 매칭 + Stride Warping

Start 는 Stop 의 거울상에 보폭 워핑(Stride Warping) 이 얹힌다. 출발 애니메이션은 보통 큰 보폭으로 만들어지는데, 실제 가속이 느리면 보폭이 과장돼 보인다. 그래서 출발 직후에는 워핑을 약하게, 시간이 지나며 100% 로 키운다.

Start 레이어 흐름 
# [Start 진입 1 회] OnInitStartAnims (25 노드)
Convert to Sequence Evaluator
  → CalculateLocomotionDirection( Calculate Direction(Acceleration) )  # 입력 방향
  → Select[Gait]( Select[Dir](Walk/JogStartAnims) ) → Set Sequence
  → Set Explicit Time = 0
  → Set StrideWarpingStartAlpha

# [Start 매 프레임] OnUpdateStartAnims (18 노드)
Advance Time by Distance Matching            # 이동 거리로 시간 진행
  → Get Accumulated Time → ExplicitTime
  → Map Range Clamped(
        Value = ExplicitTime,
        In  = [StrideWarpingBlendInStartOffset, StrideWarpingBlendInDurationScaled],
        Out = [0.0, 1.0] )
  → Set StrideWarpingStartAlpha          # 0 → 1 로 점진 상승
"
BP 내 저자 코멘트 (원문 그대로) - OnUpdateStartAnims 의 Map Range Clamped "현재 진행 시간(Explicit Time)을 보폭 워핑 알파값으로 변환. 입력값(Value)인 Explicit Time을 입력 범위(In Range A~B)에서 출력 범위(Out Range A 0.0 ~ Out Range B 1.0)로 비례 변환하고 범위를 벗어나면 클램프 합니다. (...) 즉 '시작 애니메이션이 진행될수록 보폭 워핑을 0%에서 100%까지 점진적으로 켜는' 값을 만듭니다."

변수 3 개(StrideWarpingStartAlpha, ...BlendInStartOffset, ...BlendInDurationScaled)는 이 Map Range 의 입출력이다. 실제로 그 알파를 받아 보폭을 늘이고 줄이는 Stride Warping 노드는 레이어 구현 그래프(StartLayer)에 있다 - 섹션 05 에서 다룬다.

Pivot 레이어: 가장 복잡한 56 노드

OnUpdatePivotAnims 는 콜백 중 가장 크다(56 노드). 피벗은 "방향 전환이 진행 중인가" 를 매 프레임 다시 판정해야 하기 때문이다. 저자가 핵심 Branch 에 단 코멘트가 전체 구조를 요약한다:

"
BP 내 저자 코멘트 (원문 그대로) - OnUpdatePivotAnims 의 Branch "캐릭터의 현재 속도(Velocity)와 가속도(Acceleration) 방향을 비교해 '방향 전환(피벗)이 일어나고 있는지'를 판별하고, 피벗 중이라면 피벗 지점까지의 거리로 Distance Matching을 수행하고, 피벗이 아니라면 Distance Matching 기반으로 시간을 자연 진행시키는 로직"
Pivot 레이어 흐름 
# [Pivot 진입 1 회] OnInitPivotAnims (23 노드)
Convert to Sequence Evaluator
  → CalculateLocomotionDirection( Calculate Direction(Acceleration) )
  → Select[Gait]( Select[Dir](Walk/JogPivotAnims) )
  → Set Sequence with Inertial Blending → Set Explicit Time = 0

# [Pivot 매 프레임] OnUpdatePivotAnims (56 노드)
ExecutionSequence
  ├─[Then 0] 방향·Gait 맞는 피벗 시퀀스 선택 + Inertial Blending 교체  # 무엇을
  └─[Then 1] Branch( Dot(Norm(Velocity), Norm(Accel)) < 임계 )    # 어디를
       ├─ 피벗 중  → Predict Ground Movement Pivot Location
       │              → Distance Match to Target
       └─ 피벗 아님 → Advance Time by Distance Matching

저자가 ExecutionSequence 의 두 갈래에 단 Comment 노드 (원문 그대로): "Then 0: 방향·걸음걸이에 맞는 피벗 시퀀스 선택 및 Inertial Blending 교체 (무엇을 재생할지)" / "Then 1: 선택된 시퀀스의 재생 시간을 Distance Matching으로 이동에 동기화 (어디를 재생할지)". 그리고 Advance Time by Distance Matching 옆 Comment: "Play Rate Clamp는 거리 매칭의 안정성 장치로 캐릭터가 갑자기 멈추거나 가속하면 거리 기반 재생 속도가 튈 수 있는데, 0.75~1.25 범위가 그 한계."

ABP_Layers.CalculateLocomotionDirection - DeadZone 없는 형제

ABP_Layers 에 CalculateLocomotionDirection 라는 함수가 새로 생겼다. 이름은 Step 3 의 함수와 같지만 다른 함수다 - ABP_Base 쪽은 ...WithDeadzone 으로 7 입력(히스테리시스용), ABP_Layers 쪽은 5 입력(DeadZone 없음) 이다.

함수위치입력쓰임
CalculateLocomotionDirectionWithDeadzoneABP_Base7 (+CurrentDirection, +DeadZone)매 프레임 - 깜빡임 방지 필요
CalculateLocomotionDirectionABP_Layers5 (각도 + Fwd/Bwd 경계)레이어 진입 시 1 회 - 즉시 결정
↳
왜 진입용엔 히스테리시스가 없나 히스테리시스(DeadZone)는 매 프레임 판정할 때 경계에서 깜빡이는 걸 막는 장치다. 그런데 OnInitStartAnims / OnInitPivotAnims 의 방향 판정은 레이어에 진입하는 순간 딱 한 번 일어난다 - 한 번만 정하면 깜빡일 일이 없다. 저자 description 도 그래서 짧다: "현재 각도 기준 방향 판단". 같은 문제도 호출 빈도가 다르면 다른 도구를 쓴다는 좋은 예다. 이 함수는 OnInitStartAnims / OnInitPivotAnims / OnUpdatePivotAnims 세 곳에서 호출된다.

레이어 그래프와 콜백의 분담

이 섹션이 다룬 6 개 콜백은 레이어 그래프의 Sequence Player / Sequence Evaluator 노드에 바인딩되는 함수다. 콜백은 "그 시퀀스 노드를 어떻게 제어할지" 를 정하고, 레이어 그래프 자체는 "그 시퀀스 노드 위에 Warping 등 어떤 포즈 처리를 얹을지" 를 정한다. 후자 - Sequence 노드 배치, Orientation/Stride Warping, PivotLayer 의 PivotSM - 는 섹션 05 에서 따로 다룬다.

★
섹션 04 요약 Step 4 의 애니메이션 측은 Stop/Start/Pivot 세 레이어를 Sequence Evaluator + Distance Matching 으로 구현했다. OnInit 이 "무엇을"(방향·Gait 시퀀스 선택), OnUpdate 가 "어디를" (예측 거리 → 커브 역조회 → Explicit Time)을 맡는다. Start 에는 Stride Warping 이, Pivot 에는 매 프레임 피벗 재판정이 더 얹힌다. 같은 데이터 모델(S_DirectionalAnims)을 재사용해 새 동작을 변수 추가만으로 확장한 것이 이 섹션의 설계 교훈이다.
