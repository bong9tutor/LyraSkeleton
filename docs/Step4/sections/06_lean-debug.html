Lean: 부품은 다 있는데 한 선이 빠졌다

Step 4 에는 좌우 기울임을 위한 거의 모든 부품이 들어왔다 - BS_Lean BlendSpace 에셋, 매 프레임 계산되는 LeanAngle 변수, 그리고 CycleLayer 안의 BS_Lean Blendspace Player + Apply Additive 노드까지. 그런데 그 합성 노드가 Output Pose 체인에 연결되지 않았다. Lean 은 부품이 다 갖춰진 채 마지막 한 선이 빠진 상태다. 이 섹션은 무엇이 준비됐고 무엇이 빠졌는지를 짚고, 함께 늘어난 Debug 를 본다.

준비된 것 ② LeanAngle: 매 프레임 계산되는 변수

LeanAngle 산출 파이프라인은 섹션 03 의 SetRotationData 후반부에 실재하며, exec 체인에 정상 연결돼 있다 - 이 계산은 매 프레임 동작한다.

SetRotationData - LeanAngle 산출 
DeltaYaw  (= CurrentYaw - LastFrameYaw)
   ▼ Safe Divide( DeltaYaw / DeltaTime )      # "초당 회전 속도(deg/s)"
   ▼ Safe Divide( 각속도 / LeanInterpScale )    # LeanInterpScale = 6.0
   ▼ float * float  ◀── Select[ LocomotionDirection ]   # "뒤로 달릴때 반전"
   │     # Select 핀: Forward=1.0, Backward=-1.0, Right=0.0, Left=0.0
   ▼ Clamp Angle( Min -90, Max 90 )           # "기울임 한계 제한"
   ▼ Set LeanAngle

Clamp Angle 의 한계 -90 ~ 90 이 BS_Lean 의 X 축 범위와 정확히 일치한다. Select 값은 전/후진(±1)에만 기울임을 주고 좌우 스트레이프(0)에는 안 준다. LeanAngle 은 명백히 BS_Lean 의 X 입력으로 쓸 의도로 만들어졌다.

준비된 것 ③ 합성 노드도 배치돼 있다

섹션 05 에서 본 대로, CycleLayer 의 노드로 BS_Lean Blendspace Player (AnimGraphNode_BlendSpacePlayer)와 Apply Additive (AnimGraphNode_ApplyAdditive)가 실제로 들어 있다.

노드클래스역할
BS_Lean Blendspace PlayerAnimGraphNode_BlendSpacePlayerBS_Lean 을 LeanAngle/Gait 로 재생해 기울임 포즈 생성
Apply AdditiveAnimGraphNode_ApplyAdditive그 기울임 포즈를 베이스 로코모션 포즈에 additive 로 더함

즉 Lean 의 부품은 네 가지가 다 있다 - 에셋(BS_Lean), 입력(LeanAngle), 재생 노드 (Blendspace Player), 합성 노드(Apply Additive). UE 의 표준 Lean 구현이 갖춰야 할 것이 전부 갖춰졌다.

빠진 것: Apply Additive 가 Output Pose 에 연결되지 않았다

프로젝트 저자 확인 결과, BS_Lean Blendspace Player 와 Apply Additive 는 CycleLayer 그래프에 배치만 됐고 Output Pose 체인에는 연결되지 않았다. 그래서 CycleLayer 의 실제 포즈는 Sequence Player → Orientation Warping → Stride Warping → Output Pose 로만 흐르고, BS_Lean 가지는 옆에 떠 있다. 화면에는 기울임이 나오지 않는다.

그래서 Step 4 의 Lean 은 어디까지 왔나

"한 선만 이으면 되는" 상태 Lean 은 Step 4 에서 사실상 완성 직전까지 왔다. 에셋·변수·재생 노드·합성 노드가 다 있으니, 남은 일은 Apply Additive 의 출력을 CycleLayer 의 Output Pose 체인에 잇고 BS_Lean Blendspace Player 의 X/Y 핀에 LeanAngle / Gait 를 연결하는 것뿐이다. 기능을 "부품 배치 → 배선" 순으로 만들 때 흔히 나오는 중간 상태이며, 다음 Step 의 가장 작은 출발점이다.

S_DebugSetting: 디버그 필드 2 → 3

Step 3 신규였던 S_DebugSetting 에 필드가 하나 늘었다:

필드타입기본값Step게이트 대상
ShowGaitDataboolTrueStep 3CurrentGait 출력
ShowLocomotionDataboolTrueStep 3속도/각도/방향 + 화살표
DistanceMatchingboolTrueStep 4정지 예측 위치 시각화

ABP_Base.Debug 그래프는 Step 3 의 20 노드에서 Step 4 에 37 노드로 커졌다. Sequence 로 세 갈래를 치고 각 갈래를 S_DebugSetting 의 bool 로 게이트한다:

ABP_Base::Debug (3 갈래) 
FunctionEntry → Sequence
  ├─ Branch( DebugSettings.ShowGaitData )
  │     └─true→ DebugPrintString( CurrentGait → Enum to String )
  ├─ Branch( DebugSettings.ShowLocomotionData )
  │     └─true→ 속도/각도/방향 출력 + DebugDrawVelocity x2
  │             (CharacterVelocity, Acceleration2D 화살표)
  └─ Branch( DebugSettings.DistanceMatching )   # Step4 신규
        └─true→ Predict Ground Movement Stop Location
              → Draw Debug Capsule   # 정지 예상 지점에 캡슐

세 번째 갈래의 Branch 조건은 DebugSettings.DistanceMatching 에 연결돼 있다. 이 bool 을 끄면 정지 예측 캡슐(섹션 04 의 Predict Ground Movement Stop Location 을 눈으로 보는 도구)이 사라진다. Step 4 의 핵심 기법인 Distance Matching 을 디버깅하기 위한 전용 시각화다.

참고: 헬퍼 DebugDrawVelocity 는 Step 3 의 (Velocity, ArrowLength, LineColor) 에서 Step 4 에 Text 인자가 붙어 4 입력이 됐다. BP_LsCharacter.DebugEventGraph(Numpad +/- → Global Time Dilation)는 Step 3 과 동일하다.

★
섹션 06 요약 Step 4 의 Lean 은 부품이 전부 갖춰진 미완 기능이다 - BS_Lean 에셋, LeanAngle 산출 로직, CycleLayer 의 Blendspace Player + Apply Additive 노드까지 다 있고, 마지막 Output Pose 연결 한 선만 빠졌다. Debug 쪽은 S_DebugSetting 에 DistanceMatching 필드가 붙어, Step 4 의 핵심 기법인 거리 매칭을 화면에서 검증한다 - 디버그 on/off 를 데이터(struct 필드)로 노출하는 Step 3 의 패턴 그대로다.
