SECTION 01 · 개요

Step 4 가 추가한 것: 이동 전이 상태 + Distance Matching + Warping

Step 3 는 Cycle 을 4 방향으로 갈랐지만, 캐릭터는 여전히 "가만히 있다 / 순항한다" 두 상태뿐이었다. Step 4 는 그 사이의 전이 동작 - 멈춰 있다 출발(Start), 달리다 정지(Stop), 달리는 중 방향을 꺾는 급선회(Pivot) - 를 LocomotionSM 의 정식 상태로 넣었다. 세 동작은 Distance Matching 으로 발과 땅을 묶고, 레이어 그래프마다 Orientation / Stride Warping 으로 적은 애님으로 임의 방향·보폭을 메운다. 좌우 기울임용 BS_Lean 은 에셋·데이터·합성 노드까지 준비됐지만 Output 연결이 빠진 미완 상태다. 이 문서는 그 작업 결과물을 Monolith MCP 로 분석하고 Step 3 와 비교한다.

한 문장 요약

매 프레임 워커 스레드에서 속도·가속도·회전을 모아 "지금 가속 중인가 / 어느 쪽으로 꺾이는가" 를 판정하면, LocomotionSM 의 5 상태(Idle/Cycle/Stop/Start/Pivot) 가 그에 맞는 ALI_Animation 레이어를 골라 호출하고, 각 레이어 그래프는 Sequence 소스 + Distance Matching + Orientation/Stride Warping 으로 적은 애님을 임의 방향·속도·보폭에 맞춰 미끄러짐 없이 재생한다.

i
이번엔 상태를 쪼갰다 - 그런데 방향이 아니라 "동작 페이즈" 다 Step 3 문서는 "방향을 스테이트로 안 쪼갰다" 를 설계 미덕으로 강조했다. Step 4 는 처음으로 LocomotionSM 에 상태를 3 개 더했지만, 쪼갠 축이 다르다. 추가된 Stop/Start/Pivot 은 방향(F/B/R/L)이 아니라 이동의 국면(출발 / 정지 / 급선회)이다. 방향은 Step 3 그대로 LocomotionDirection 변수 + Select 로 남기고, Orientation Warping 이 4 방향 사이 임의 각도를 메운다. "한 번 일어나고 끝나는 전이 동작" 만 상태로 만들었다 - 축이 다르면 도구도 다르다.

이 Step 의 학습 가치 Step 4 는 세 개의 큰 주제를 동시에 가르친다. (1) State Machine 설계 - "언제 상태를 만들고 언제 변수로 두는가". (2) Distance Matching - 루트 모션과 무브먼트를 발 단위로 묶는 기법. (3) Animation Warping - 적은 애님으로 임의 방향·보폭을 메우는 런타임 보정. 게다가 저자가 BP 안에 실패와 수정 과정(MaxTransitionsPerFrame 버그, 캐싱 타이밍 fix)을 코멘트로 남겨, "왜 이렇게 됐는가" 를 결과가 아니라 과정으로 보여준다 - 섹션 07 의 핵심.
