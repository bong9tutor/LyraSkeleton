Step 4 허브 › 02. LocomotionSM 상태 확장
SECTION 02 · State Machine

LocomotionSM: 2 상태에서 5 상태로

Step 3 까지 LocomotionSM 은 Idle 과 Cycle 뿐이었다. Step 4 는 그 사이에 Stop / Start / Pivot 세 상태를 끼워 넣고, 13 개의 전이 룰로 묶었다. 각 상태는 ALI_Animation 의 대응 레이어를 호출만 하는 2 노드짜리 얇은 상태다. 이 섹션은 5 상태와 그 사이를 잇는 전이 조건을 따라간다.

ALI_Animation: 레이어 인터페이스 2 → 5

변화의 출발점은 인터페이스다. ALI_Animation 은 AnimLayerInterface 를 부모로 하는 애니메이션 레이어 인터페이스이며, 함수(레이어)가 5 개로 늘었다.

레이어 함수Step대응 SM 상태
IdleLayerStep 1~Idle
CycleLayerStep 2~Cycle
StopLayerStep 4Stop
StartLayerStep 4Start
PivotLayerStep 4Pivot

5 개 레이어 함수는 모두 입력·출력 핀이 없다 - 포즈를 반환하는 레이어 시그니처다.

5 상태는 전부 "레이어를 부르는 통로" 다

5 상태의 내부는 모두 정확히 2 노드다 - Output Animation Pose 와 Linked Anim Layer 하나. 즉 상태 자체에는 포즈 로직이 없고, 대응하는 ALI_Animation 레이어를 호출만 한다.

상태내부 노드 (2 개)position
Idle entryOutput Animation Pose ← ALI_Animation - IdleLayer (Linked Anim Layer)[176, 0]
CycleOutput Animation Pose ← ALI_Animation - CycleLayer[432, 272]
StopOutput Animation Pose ← ALI_Animation - StopLayer[176, 272]
StartOutput Animation Pose ← ALI_Animation - StartLayer[432, 0]
PivotOutput Animation Pose ← ALI_Animation - PivotLayer[448, 432]
i
"얇은 상태" 가 곧 Step 1 의 레이어드 설계다 상태가 포즈를 직접 만들지 않고 레이어를 호출만 하므로, 실제 애니메이션 로직은 전부 ABP_Layers(또는 무기별 ABP_Pistol/ABP_UnArmed)의 레이어 구현으로 간다. 그래서 ABP_Base 는 "언제 어느 상태인가"(SM)만 책임지고, "그 상태에서 무엇을 재생하나"는 ABP_Layers(섹션 04)가 책임진다. Step 1 의 "얇은 레이어" 가 상태 머신 레벨에서도 그대로 유지됐다.

상태 다이어그램 (13 전이)

5 상태 + PivotAlias(상태 별칭) 와 13 개 전이를 그리면:

                  bIsAccelerating
        ┌──────────────────────────────▶ Start ───────┐

# PivotAlias = 상태 별칭(State Alias). 여러 상태에서 Pivot 진입을 한 룰로 묶는다.

13 전이의 룰

각 전이가 어떤 변수/연산으로 판정되는지를 보면, 핵심 변수는 bIsAccelerating(가속 입력 여부), CharacterVelocity2D(실제 속도), Acceleration2D(입력 방향) 다.

전이크로스페이드전이 룰의미
Cycle → Stop0.30NOT bIsAccelerating순항 중 입력을 떼면 정지 시작
Stop → Idle0.25VLenXY(Velocity2D)≈0 AND VLenXY(Acceleration2D)≈0속도·가속도 모두 0 = 완전 정지
Idle → Start0.15bIsAccelerating정지 중 입력이 들어오면 출발
Start → Cycle (1)0.20NearlyEqual(VLenXY(Velocity2D), …PropertyAccess)순항 속도 도달 (추정: Max Speed 비교)
Start → Cycle (2)0.20LastLocomotionDirection != LocomotionDirection출발 도중 방향이 바뀜 → Start 건너뜀
Start → Cycle (3)0.20bIsGaitChanged출발 도중 Gait(Walk/Jog) 바뀜 → 건너뜀
Start → Cycle (4)0.25(룰 노드에 Result 만)Start 시퀀스 종료 자동 전이 (추정)
Start → Stop0.25NOT bIsAccelerating출발하다 곧바로 입력을 떼면 정지
Stop → Start0.15bIsAccelerating정지하다 다시 입력 → 재출발
PivotAlias → Pivot0.30Dot(Norm(Velocity), Norm(Accel)) < 임계속도와 입력 방향이 크게 어긋남 = 급선회
Pivot → Cycle (1)0.20abs(Dot(Norm(PivotAccel2D), Norm(Velocity2D))) < 임계속도가 새 방향으로 정렬됨
Pivot → Cycle (2)0.20Was Anim Notify Triggered in Source State (Pivot)AN_TransitionToLocomotion 발생
Pivot → Stop0.20NOT bIsAccelerating피벗 도중 입력을 떼면 정지

전이는 모두 13 개다. 위 표 12 행에 Pivot → Cycle 자동 계열을 합쳐 13 에 대응한다. 크로스페이드 값은 소수 2 자리로 반올림했다 (예: 0.30000001192 → 0.30). 전이 룰의 노드 구성은 보이나 일부 핀 상수/부등호 세부는 그래프 요약 범위 밖이라 해당 부분은 "(추정)" 으로 표기했다.

AN_TransitionToLocomotion: 빈 노티파이가 전이를 연다

신규 자산 AN_TransitionToLocomotion 은 AnimNotify 를 상속한 로직이 전혀 없는 빈 클래스다 - 그래프·변수·함수가 모두 0 인 data-only 블루프린트.

i
로직이 없는 게 핵심이다 이 노티파이는 무언가를 실행하지 않는다. 그저 Pivot 애니메이션 시퀀스의 특정 프레임에 꽂혀 "여기서 피벗이 끝난다" 를 표시할 뿐이다. 실제로 그 신호를 읽는 쪽은 전이 Pivot → Cycle (2) 의 룰 노드 Was Anim Notify Triggered in Source State (Pivot) - Pivot 상태가 재생 중인 시퀀스에서 이 노티파이가 지나갔는지 검사한다. 노티파이가 지나가면 전이 성립. "데이터(마커)로 시점을 노출하고, 판정은 전이가 한다" - Step 3 의 "바뀔 값은 데이터로" 와 같은 결.

저자 디버깅 기록: MaxTransitionsPerFrame 3 → 1

AnimGraph 의 LocomotionSM 노드에 저자가 단 코멘트는, 이번 Step 에서 실제로 터졌던 버그와 그 수정을 통째로 적은 디버깅 일지다. 그대로 인용한다:

ABP_Base.AnimGraph - LocomotionSM 노드 코멘트 (원문 그대로) 
[LocomotionSM] MaxTransitionsPerFrame: 3 → 1

■ 변경 이유
Start → Cycle 트랜지션 룰 중 다음 조건이 존재:
  LastFrameVelocityLocomotionDirection != CurrentFrameVelocityLocomotionDirection
(직전 프레임과 현재 프레임의 이동 방향이 다르면 Start를 건너뛰고 Cycle로 전환)

■ 발생했던 버그
기본값(3) 사용 시, 한 프레임 내에 트랜지션이 여러 번 평가됨.
LastFrame / CurrentFrame 변수는 프레임당 1회만 갱신되므로,
같은 프레임 내 2회차 이후 평가에서 변수의 시간적 의미가 깨져
방향 변화가 없는데도 조건이 True로 판정됨.

결과: 오른쪽/왼쪽/뒤로 이동 시 Start 애니메이션이 재생되지 않고
      즉시 Cycle로 전환되는 문제 발생 (Forward만 정상 동작).

■ 해결
트랜지션 평가 횟수를 프레임당 1회로 제한하여,
변수 갱신 주기(1회/프레임)와 동기화.

■ 주의
이 값을 다시 올리면 위 버그가 재발하므로 1로 유지할 것.
Conduit이나 연쇄 트랜지션 추가 시 별도 검토 필요.

이 코멘트는 위 전이 표의 Start → Cycle (2) (LastLocomotionDirection != LocomotionDirection)를 정확히 가리킨다. LastLocomotionDirection 은 ABP_Base 의 신규 변수이며 프레임당 1 회만 갱신되는데(섹션 03), 엔진 기본값 MaxTransitionsPerFrame = 3 은 한 프레임에 전이 그래프를 최대 3 번까지 평가한다. 2 회차 평가에서는 "직전 프레임" 변수가 이미 이번 프레임 값과 같아져 비교가 무의미해지고, 엉뚱하게 조건이 참이 되어 Start 가 통째로 스킵됐다.

↳
이 한 줄이 담은 교훈 MaxTransitionsPerFrame 값(1) 자체는 상태 머신 노드 속성이라 그래프에 수치로는 보이지 않지만, 코멘트가 그 변경을 명문화했다. 이 한 줄은 "프레임당 1 회 갱신되는 변수를, 프레임당 여러 번 평가되는 곳에서 쓰면 시간 의미가 깨진다" 는 일반 교훈을 담는다 - "직전 프레임" 변수는 갱신 주기와 소비 주기가 같아야 한다.
★
