OnCycleUpdate: 2 단 중첩 Select (실측 17 노드)

get_node_details 로 Select 3 개의 핀 연결을 그대로 떴다. 핵심은 Select 가 3 개이고, 둘은 방향 분기, 하나는 Gait 분기라는 점이다.

OnCycleUpdate Select 배선 (실측 connected_to) 
# Select_2 : Walk 묶음의 방향 분기
Select_2.Index ← PropertyAccess_2   # = ABP_Base.LocomotionDirection
  NewEnumerator0 ← WalkCycleAnims.Forward
  NewEnumerator1 ← WalkCycleAnims.Backward
  NewEnumerator2 ← WalkCycleAnims.Right
  NewEnumerator3 ← WalkCycleAnims.Left
  ReturnValue ──┐

# Select_1 : Jog 묶음의 방향 분기 (구조 동일)
Select_1.Index ← PropertyAccess_0   # = ABP_Base.LocomotionDirection
  NewEnumerator0..3 ← JogCycleAnims.{Forward/Backward/Right/Left}
  ReturnValue ──┐

# Select_0 : Gait 분기 (바깥쪽)
Select_0.Index ← PropertyAccess_1   # = CurrentGait (E_Gait)
  NewEnumerator0 ← Select_2.ReturnValue   # Walking → Walk 방향 결과
  NewEnumerator1 ← Select_1.ReturnValue   # Jogging → Jog 방향 결과
  ReturnValue → Set Sequence with Inertial Blending.Sequence
                  → Set SequencePlayer → Return

한 줄로 줄이면:

선택 식 (실측 배선 기반) 
CycleSequence =
   Select[ CurrentGait ](
       Walking : Select[ LocomotionDirection ]( WalkCycleAnims.F/B/R/L ),
       Jogging : Select[ LocomotionDirection ]( JogCycleAnims.F/B/R/L )
   )
→ Set Sequence with Inertial Blending   # 부드러운 시퀀스 교체
i
왜 enum 값 순서가 중요한지 (섹션 02 복선 회수) Select 입력 핀 이름이 NewEnumerator0~3 이고, 이는 E_LocomotionDirections(Forward0/Backward1/Right2/Left3) 의 내부 이름과 같다. 그래서 LocomotionDirection 값이 그대로 Select 인덱스가 되어, struct 필드 순서 (Forward/Backward/Right/Left)와 1:1 로 맞물린다. enum/struct 순서를 따로 안 맞추면 방향이 어긋난다.

측정 한계: FunctionEntry → Branch(IfThenElse_0) 로 시작하며 한 분기는 Convert to Sequence Player → 위 Select 체인, 다른 분기는 Log String (시퀀스 플레이어 변환 실패시 로그)로 측정됨. Branch 의 정확한 조건 핀 식은 노드 요약 범위 밖이라 "유효성 가드(추정)" 로 둔다.

"
저자 코멘트 (실측) - "왜 하드 스위치인데 부드러운가" Select 는 4 칸 이산 스위치라 방향이 F→R 로 튄다. 그런데 끊겨 보이지 않는 이유를 저자가 두 곳에 적어 뒀다: OnIdleUpdate 의 Set Sequence with Inertial Blending 노드 코멘트 "Sequence Player의 시퀀스를 부드럽게 전환하는 함수" (같은 함수가 OnCycleUpdate 끝에도 쓰임), 그리고 ABP_Base.AnimGraph 의 Inertialization 코멘트 "이전 포즈의 이동·회전 관성을 유지하며 수행하는 고급 포즈 블렌딩". 즉 이산 선택 + 관성 블렌딩 이 저자의 의도다 - 의도 분석 전문은 섹션 05.

ABP_Base Debug 그래프 (실측 20 노드)

Debug() (category Debug)는 Sequence 로 두 갈래를 친 뒤, 각 갈래를 S_DebugSetting 의 bool 로 게이트한다 (실측 exec):

ABP_Base::Debug (실측) 
FunctionEntry → Sequence
  ├─[0]→ Branch( DebugSettings.ShowGaitData )
  │         └─true→ DebugPrintString( Get CurrentGait → Enum to String )
  └─[1]→ Branch( DebugSettings.ShowLocomotionData )
            └─true→ DebugPrintFloat( VectorLengthXY(CharacterVelocity2D) )
                  → DebugDrawVelocity( CharacterVelocity )
                  → DebugPrintFloat( LocomotionAngle )
                  → DebugPrintString( LocomotionDirection → Enum to String )

게이트되는 헬퍼 3 종도 get_functions 로 시그니처 확인됨 (전부 category Debug):

  • DebugPrintString(Key: name, Value: string)
  • DebugPrintFloat(Key: name, Value: double, TextColor: LinearColor)
  • DebugDrawVelocity(Velocity: Vector, ArrowLength: double, LineColor: LinearColor)
↳
디버그도 데이터 구동 on/off 가 코드 주석/노드 삭제가 아니라 S_DebugSetting 의 bool 필드(기본 True)다. 섹션 03 의 "임계값을 핀으로 노출", 섹션 02 의 "디버그를 struct 로" 와 같은 결 - Step 3 전반의 설계 일관성: 바뀔 수 있는 값은 데이터로 뺀다.

BP_LsCharacter DebugEventGraph (실측 12 노드)

BP_LsCharacter 는 변수(3)·함수(2) 수가 Step 2 와 같고, 그래프만 3 → 4 로 늘었다 (list_graphs: EventGraph 36 / DebugEventGraph 12 / UserConstructionScript 1 / SetGaitAndApplySettings 36). 새 DebugEventGraph 의 실측 흐름:

DebugEventGraph (실측) 
InputDebugKey "Debug Key Num +" ─┐
InputDebugKey "Debug Key Num -" ─┤
                                  ├→ Set Global Time Dilation( Get Global Time Dilation ± step )
                                  └→ Print String( Append( "...", To String (Float) ) )

Numpad + / - 디버그 키로 Global Time Dilation 을 올리고 내리고, 현재 값을 화면에 찍는다. 방향 전환 같은 빠른 로코모션을 슬로모션으로 눈으로 확인하기 위한 도구다. InputDebugKey 는 개발 빌드 전용이라 패키지 실행에는 영향이 없다.

자식 ABP 는 또 안 건드렸다 (실측)

ABP_Pistol / ABP_UnArmed 는 get_abp_info 기준 Step 2 와 동일: parent_class: ABP_Layers_C, variable_count: 0, graphs: ["EventGraph"], state_machine_count: 0, interface 없음. 방향성/디버그 로직이 전부 부모 ABP_Layers / ABP_Base 에 들어갔으므로 얇은 자식은 손댈 필요가 없었다 - Step 1 에서 분석하고 Step 2 에서 입증된 "작업 격리" 가 또 한 번 통했다.
