갱신 핀 기본값이 get_node_details 로 측정된다
Step 1 ~ 2 메모: "핀 기본값 / Select 인덱스는 응답에 없음, (추정)/에디터 확인". Step 3 실측: blueprint_query.get_node_details 의 pins[].default_value 가 CalculateLocomotionDirection 호출 노드에서 -130.000000 / 130 / -50 / 50 / DeadZone 20 을 그대로 반환했다. Select 노드도 connected_to 로 옵션 핀 배선이 전부 드러난다. 전이 룰(get_transitions)에는 여전히 상수가 없지만, 일반 그래프의 호출 노드 핀 상수/배선은 get_node_details 로 측정 가능 (그래프 요약 액션과 별개).
유지 Enum/Struct 의 referenced_by 가 비어 있다
E_LocomotionDirections / S_DirectionalAnims / S_DebugSetting 모두 project_query.find_references 의 referenced_by 가 []. UserDefinedEnum/Struct 역참조는 Monolith 응답에 안 잡힌다. 소비처 확인은 소비 BP/ABP 의 get_abp_variables + Select 핀 connected_to(필드 GUID 일치)로 cross-check 했다.
cross-check 이번 핵심 식별자의 2 액션 확인
LocomotionDirection = get_abp_variables + CalculateLocomotionDirection 출력 + Switch 노드. S_DirectionalAnims 필드 = get_asset_details GUID + OnCycleUpdate Select 핀 connected_to(동일 GUID). BTSUA 5 단 = get_graph_summary exec 체인 + 각 함수 get_functions 시그니처. 그래프명은 메모리 quirk 대로 get_functions(정상 철자)를 1 차 자료로 썼다.
한계 함수 내부 부등호 / Branch 조건식
CalculateLocomotionDirection 72 노드의 토폴로지(Switch/InRange/±DeadZone/OR/Branch)는 보이나, Right/Left 의 50 ~ 130 세부 경계 부등호 조합과 OnCycleUpdate 시작 Branch 의 조건식은 노드 요약 범위 밖이라 본문에서 "(추정)/에디터 확인" 으로 명시했다.

아직 빈 영역 / 다음 단계 후보

  1. 방향 임계의 완전 외부화 - 현재 ±50/±130/DeadZone 20 은 호출 노드의 핀 리터럴. Step 2 의 S_GaitSetting 처럼 struct(예: S_DirectionSetting)나 curve 로 빼면 Gait 별/캐릭터별 튜닝과 데이터 검증이 쉬워진다.
  2. 방향 시퀀스 채우기 / BlendSpace 전환 - S_DirectionalAnims 4 필드 기본값이 None. 4 방향 시퀀스를 채우거나, 이산 Select 대신 각도 기반 BlendSpace 로 가면 대각선 보간이 자연스러워진다 (지금은 4 칸 하드 스위치 + 관성 블렌딩).
  3. Stop/Start, Pivot, Lean - 방향이 생겼으니 정지/출발 전이, 급선회(pivot), 가속 기울임(lean) 이 다음 자연 확장. LocomotionAngle 변화율을 이미 계산 가능.
  4. Weapon ↔ AnimBP 동기화 + C++ 이식 - Step 1 ~ 2 로드맵의 미해소분. 데이터·enum 우선 이식 원칙에 E_LocomotionDirections/S_DirectionalAnims 합류.
