ABP_Base: 속도에서 4 방향 enum 까지

Step 2 의 BlueprintThreadSafeUpdateAnimation 은 SetVelocityData 한 줄이었다. Step 3 는 같은 진입점이 5 단 파이프라인 으로 늘어, 매 프레임 워커 스레드에서 원시 데이터를 모으고 각도를 구해 4 방향 enum 으로 굳힌다. 이 섹션은 그 5 단계를 노드 실측으로 따라간다.

1 단계: 5 단 스레드세이프 파이프라인

BlueprintThreadSafeUpdateAnimation(DeltaTime) 의 실측 exec 체인 (9 노드):

  → SetLocationData           # Step3: WorldLocation

Step 2 메모리의 한국어 코멘트("PropertyAccess 를 쓰는 이유는 멀티 쓰레드(WorkerThread) 안정성")가 그대로 적용된다 - 아래 2 ~ 3 단계의 데이터 수집이 전부 PropertyAccess 노드다.

2 단계: 원시 데이터 수집 (Location / Rotation)

두 함수 모두 측정상 3 노드로 동일한 모양 - 군더더기 없는 캐시 함수다.

3 단계: UpdateOrientationData - 각도 산출

저자 설명: "방향 판단에 필요한 원시 Orientation 데이터들을 일괄 갱신". 실측 5 노드:

UpdateOrientationData (실측) 
FunctionEntry → Set LocomotionAngle
   ▲
   └── Calculate Direction(
           Velocity = Get CharacterVelocity2D,

Calculate Direction 은 엔진 UKismetAnimationLibrary::CalculateDirection - 속도 벡터를 기준 회전으로 투영해 -180 ~ 180 도 의 상대 이동 각도를 돌려준다. 그 결과가 LocomotionAngle (real) 에 저장된다. 여기까지가 "연속값" 단계다.

4 단계: CalculateLocomotionDirection - 연속 각도를 4 방향으로

Step 3 의 심장. get_functions 가 준 시그니처와, BP 안에 저자가 직접 적은 한국어 설명 전문:

CalculateLocomotionDirection - 시그니처 (실측) 
# category: LocomotionDirection · is_pure: false
CalculateLocomotionDirection(
    CurrentLocomotionAngle : double,
    BackwardMin : double,  BackwardMax : double,
    ForwardMin  : double,  ForwardMax  : double,
    CurrentDirection : byte,            # 히스테리시스 체크용 (이전 방향)
    DeadZone : double
) -> ReturnValue : byte                 # E_LocomotionDirections

# [BP 내 저자 설명 - 응답 그대로]
# 이동 각도를 4방향(Forward/Backward/Left/Right) 중 하나로 판단합니다.
# [특징]
#  - 히스테리시스 적용으로 경계각 깜빡임 방지
#  - 데드존 파라미터로 안정성 조정 가능
#  - Thread Safe 지원
# [입력]
#  - CurrentLocomotionAngle: 이동 각도 (-180 ~ 180)
#  - CurrentDirection: 현재 방향 (히스테리시스 체크용)
#  - DeadZone: 유지 영역 확장 폭
# [반환] E_LocomotionDirections (Forward/Backward/Left/Right)

호출부에서 측정한 임계값 (get_node_details)

이 함수가 BlueprintThreadSafeUpdateAnimation 에서 호출되는 노드의 입력 핀 default_value 를 실측했다. 핀 기본값이 응답에 그대로 나왔다 (Step 2 메모의 "핀 기본값 측정 불가" 한계가 get_node_details 에서는 깨진다 - 섹션 05):

입력 핀측정된 값 / 연결의미
CurrentLocomotionAngle← Get LocomotionAngle (연결)3 단계 산출값
ForwardMin / ForwardMax-50.0 / 50.0전방 판정 폭 ±50°
BackwardMin / BackwardMax-130.0 / 130.0후방 경계 ±130°
CurrentDirection← Get LocomotionDirection (연결, 피드백)직전 결과 = 히스테리시스 기준
DeadZone20.0유지 영역 확장 폭(°)
ReturnValue→ Set LocomotionDirection이번 프레임 방향

측정으로 본 4 방향 분할

측정된 임계값(±50 / ±130)으로 -180 ~ 180 각도 구간을 그리면:

이동 각도 → 방향 (DeadZone 미적용 기준 구간) 
  -180 ┃ -130        -50    0    50         130 ┃ 180
       ┃              │            │             ┃
  Back ┃◀── Left ────▶│◀── Forward ──▶│◀─ Right ─▶┃ Back
 (|a|≥130)            (|a|≤50)              (50<|a|<130, 부호로 좌/우)

  · Forward : ForwardMin ≤ a ≤ ForwardMax        (= -50 ~ 50)
  · Backward: a ≤ BackwardMin 또는 a ≥ BackwardMax (= |a| ≥ 130)
  · Right   : 양의 측면 구간 (50 ~ 130 부근)
  · Left    : 음의 측면 구간 (-130 ~ -50 부근)
  · DeadZone(20): "현재 방향" 의 유지 구간을 ±20° 넓혀 경계 깜빡임 차단
i
측정된 것 / 추정인 것 구분 측정된 사실: 입력 임계값(±50/±130/DeadZone 20), 출력이 LocomotionDirection 으로 감, 함수 내부에 Switch on E_LocomotionDirections + In Range (Float) + float ± DeadZone + OR Boolean + 다수 Branch/Return (72 노드)가 존재. 각 방향 경계의 정확한 부등호 조합(특히 Right/Left 의 50 ~ 130 분할 세부)은 72 노드 토폴로지에서 보이지만 핀별 상수 일부는 노드 요약에 안 나와, 위 구간도는 측정된 임계값에 기반한 합리적 재구성이다 (정밀 경계는 에디터 확인).

히스테리시스: 왜 CurrentDirection 을 되먹이나

함수 내부의 Switch on E_LocomotionDirections 노드에 저자가 단 코멘트 (실측):

"
BP 내 저자 코멘트 (응답 그대로) "데드존 적용: 각 방향의 유지 영역이 데드존만큼 확장되어, 한번 결정된 방향은 더 큰 각도 변화시 적용"

즉 입력 CurrentDirection(= 직전 프레임의 LocomotionDirection) 으로 먼저 분기 한 뒤, "지금 방향" 의 경계만 DeadZone(20°) 만큼 넓혀서 판정한다. 대각선 근처에서 각도가 미세하게 떨려도 방향이 핑퐁하지 않는다. 이래서 출력 변수 LocomotionDirection 이 함수 입력으로 되먹임(feedback) 되는 것이다.

★
섹션 03 요약 Step 3 의 ABP_Base 는 "원시 수집(Velocity/Location/Rotation) → 각도(Calculate Direction) → 안정화된 이산 방향(CalculateLocomotionDirection + 히스테리시스)" 을 한 스레드세이프 파이프라인으로 묶었다. 결과물 LocomotionDirection 한 변수가 다음 섹션(OnCycleUpdate)에서 시퀀스 선택의 키가 된다.
