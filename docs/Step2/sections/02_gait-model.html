Gait 데이터 모델과 CMC 적용

이동 상태를 표현하는 E_Gait enum, 상태별 무브먼트 값을 담는 S_GaitSetting struct, 그리고 이 둘을 BP_LsCharacter 가 맵으로 보관하고 SetGaitAndApplySettings 함수로 CharacterMovementComponent 에 적용하는 흐름을 실측한다.

(1) E_Gait - 이동 상태 enum

실측: project_query.get_asset_details(/Game/ALS/Enums/E_Gait)

UserDefinedEnum · E_Gait 
E_Gait  (UserDefinedEnum, entry_count = 2)
  ├── NewEnumerator0  →  display "Walking"  value 0
  └── NewEnumerator1  →  display "Jogging"  value 1
i
E_Weapon 과 동일한 패턴 Step 1 의 E_Weapon(UnArmed=0, Pistol=1) 과 같은 2 엔트리 UserDefinedEnum 형태. 실제 enum 식별자는 NewEnumerator0/1 이고 표시 이름만 Walking/Jogging 이다. BP 의 byte 변수와 맵 키가 이 내부 식별자를 그대로 쓴다 (NewEnumerator0 = Walking).

(2) S_GaitSetting - 상태별 CMC 파라미터 묶음

실측: project_query.get_asset_details(/Game/ALS/Structs/S_GaitSetting) · 신규 폴더 Content/ALS/Structs/

필드 (표시명)타입대응 CMC 프로퍼티
MaxWalkSpeeddouble최대 이동 속도
MaxAccelerationdouble가속도

왜 struct 로 묶나 6 개 값이 "한 Gait 단계의 무브먼트 프로파일" 이라는 하나의 의미 단위다. 개별 변수 6 개를 흩어 두는 대신 struct 1 개로 묶으면, 아래의 Map<E_Gait, S_GaitSetting> 한 줄로 "상태 → 프로파일" 테이블이 깔끔하게 표현된다. C++ 이식 시 USTRUCT() 한 개로 1:1 대응된다.

GaitSettings 맵의 측정된 기본값

실측: get_variables 의 default_value. Walking 항목은 4 개 필드만, Jogging 항목은 5 개 필드만 명시되어 있고 나머지는 struct 기본값(0.0 / False)이다. 측정된 값을 그대로 옮긴다.

측정된 그대로 - 추정 보정 안 함 BrakingFriction 필드는 두 키 어디에도 default 에 명시되지 않았다 (struct 기본값 0.0 적용). Walking 의 bUseSeparateBrakingFriction 도 default 문자열에 없다. 이는 의도된 값일 수도, 에디터에서 채워 넣는 중일 수도 있다. 문서는 측정값만 옮기고 "왜 비었나" 는 추정하지 않는다.

(4) SetGaitAndApplySettings - 상태 저장 + CMC 적용 함수

실측: blueprint_query.get_functions + get_graph_summary(graph_name="SetGaitAndApplySettings") (node_count = 36)

SetGaitAndApplySettings(Gait : byte) 신규 함수
입력Gait : byte 출력 없음 36 노드

함수 description (저자 작성, 한국어 원문 그대로): "캐릭터의 이동 상태 저장 및 변경된 이동 상테에 따른 CMC 설정 변경" (원문의 "상테" 표기 그대로 인용)

SetGaitAndApplySettings (실측 노드 흐름) 
[FunctionEntry: SetGaitAndApplySettings(Gait)]
       ↓
[Branch IfThenElse_1]   # 가드: 상태가 실제로 바뀔 때만
   조건: Not Equal (Enum)  Get CurrentGait  !=  Get Gait
   │ True
   ↓
[Set CurrentGait]  = Gait
       ↓
[Message OnGaitChanged(Gait)]   # comment: "ABP 에 캐릭터의 이동상태 변경을 알림"
   # 대상: Get Mesh → Get Anim Instance (BPI_Animation 메시지)
       ↓
[Branch IfThenElse_0]
   │ True                                  │ False
   ↓                                       ↓
Get GaitSettings.Find(Gait)            [Format Text] ← Enum to String(Gait)
   → Break S_GaitSetting                        ↓
   ↓                                       [Print Text]   # 디버그 출력
Get CharacterMovement 에 순서대로 Set:
   MaxWalkSpeed → MaxAcceleration → BrakingDecelerationWalking
   → BrakingFrictionFactor → BrakingFriction → bUseSeparateBrakingFriction
i
설계 포인트 3 가지 (실측 기반)
  • enum 부등호 가드: CurrentGait != Gait 일 때만 진행. 같은 상태로의 중복 호출에서 메시지/CMC 재적용을 막는다 (입력이 매 프레임 들어와도 안전).
  • 통지 먼저, 적용 나중: Set CurrentGait → OnGaitChanged 메시지 → 그다음 CMC 값 적용 순서. AnimBP 통지와 무브먼트 적용이 한 함수에 모여 있다.
  • 데이터 주도: 속도 값을 코드에 하드코딩하지 않고 GaitSettings.Find(Gait) 로 맵에서 꺼내 Break 후 적용. 새 Gait 단계는 enum + 맵 엔트리만 추가하면 된다.
★
