AnimGraph 의 구조 교체: 슬롯 → 스테이트 머신

Step 2 의 가장 큰 구조 변경. ABP_Base 의 AnimGraph 가 Step 1 의 단일 LinkedAnimLayer(IdleLayer) 슬롯에서 LocomotionSM 스테이트 머신 (Idle ↔ Cycle) 으로 바뀌었고, ALI_Animation 에 CycleLayer 가 추가되었으며, ABP_Layers 가 실제 시퀀스 갱신 로직을 갖췄다.

단일 슬롯이 사라진 게 아니라 스테이트 머신 안으로 들어갔다 get_linked_layers(ABP_Base) 는 이제 [] 로 측정된다. AnimGraph 최상위에서 직접 보이던 LinkedAnimLayer 노드가 사라지고, Idle/Cycle 두 state 각각이 내부에서 ALI_Animation 의 IdleLayer / CycleLayer 를 평가하는 구조로 재배치되었다. Inertialization 은 Step 1 과 동일하게 최종 블렌딩을 담당.

(3) LocomotionSM - 이 프로젝트 최초의 스테이트 머신 (실측)

실측: animation_query.get_state_machines + get_transitions

LocomotionSM (entry = Idle, state 2, transition 2) 
          ┌─────────────────────────────────────────────┐
          │                                             │
   (entry)│   [Idle]                            [Cycle]
          └──▶  Idle ───────────────────────────────▶  Cycle
                  rule: Vector Length XY(CharacterVelocity2D) > 임계값
                       ◀───────────────────────────────
                  rule: Vector Length XY(CharacterVelocity2D) Nearly Equal 0
                cross_fade_duration = 0.2  (양방향 동일)
★
전이 규칙이 측정됐다 - Step 1 한계의 갱신 Step 1 문서는 "Monolith 가 State 전이 룰 그래프를 응답에 안 준다" 고 명시했다. Step 2 실측에서는 get_transitions 가 rule_nodes 배열을 반환했다:
  • Idle → Cycle: TransitionResult ← float > float ← Vector Length XY ← Get CharacterVelocity2D
  • Cycle → Idle: TransitionResult ← Nearly Equal (Float) ← Vector Length XY ← Get CharacterVelocity2D
즉 "평면 속도 크기가 임계값보다 크면 움직임(Cycle), 0 에 가까우면 정지(Idle)" 가 측정으로 확인된다. 다만 정확한 임계 상수값(float > float 의 우변)은 노드 토폴로지에만 있고 핀 기본값은 응답에 없어, 수치는 에디터 확인 대상이다.

Property Access → Cast To ABP_Base → ReturnValue. 레이어 ABP 가 베이스(ABP_Base)의 상태(예: CurrentGait)를 워커 스레드 안전하게 읽는 통로.

  • 저자 노트(Return): "Outputs 변수명은 반드시 ReturnValue 로 설정 해야 AccessProperty 에 노출 됩니다. (엔진 강제)"
i
ABP_Layers.AnimGraph 는 여전히 Output Pose 1 개 실측상 ABP_Layers 의 AnimGraph 는 Step 1 과 동일하게 노드 1 개(Output Pose)다. 레이어의 실제 포즈 작업은 AnimGraph 가 아니라 OnIdleUpdate / OnCycleUpdate 함수(슬롯 구현) 안에서 Set Sequence with Inertial Blending 으로 SequencePlayer 를 갱신하는 방식이다. Step 1 에서 "비어 있던 슬롯" 이 정확히 이 두 함수였고, Step 2 가 그것을 채웠다.
