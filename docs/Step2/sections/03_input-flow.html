IA_Aim 입력과 BPI_Animation 통신

IA_Aim 입력이 SetGaitAndApplySettings 를 어떻게 부르는지, 그리고 그 결과를 BPI_Animation.OnGaitChanged 메시지가 어떻게 Character 에서 AnimBP 로 단방향 전달하는지를 실측한다.

① IA_Aim - 새 입력 액션

실측: project_query.get_asset_details(/Game/ALS/Inputs/InputActions/IA_Aim)

InputAction · IA_Aim 
IA_Aim  (InputAction)
  value_type           = EInputActionValueType::Boolean
  consume_input        = true
  trigger_when_paused  = false
  triggers             = []      # 기본 (별도 트리거 없음)
  modifiers            = []

Step 1 의 IA_SwitchWeapon 은 Axis1D 였지만 IA_Aim 은 Boolean 이다. "누르는 동안 on" 형태의 토글성 입력에 맞는 값 타입.

② IMC_ALS 변경 - 측정 한계 명시

실측: project_query.get_asset_details(/Game/ALS/Inputs/IMC_ALS) + git status

!
IMC_ALS 는 git 상 변경(M)되었으나 Monolith depends_on 에 IA_Aim 미반영 측정된 depends_on 은 여전히 IA_Look, IA_Move, IA_SwitchWeapon 3 개뿐. IA_Aim 이 빠져 있다. 두 가지가 겹친 결과로 본다:
  • 알려진 한계: IMC_* 의 키-IA 매핑 자체가 Monolith 응답에 안 나온다 (nodes:[]). depends_on 만 보이는데, 인덱스 시점 차이로 갱신이 지연될 수 있다.
  • 확실한 사실: BP_LsCharacter.EventGraph 에 EnhancedInputAction IA_Aim 노드가 실재한다 (아래 ③ 에서 실측). 즉 IA_Aim 은 입력으로 실제 소비되고 있다.
결론(에디터 확인 완료): IA_Aim 은 마우스 우클릭(Right Mouse Button) 에 바인딩되어 있다. Monolith 응답에는 키 매핑이 안 잡혀(nodes:[]) 측정 불가였고, 이 키 바인딩은 에디터에서 직접 확인해 보강했다.

③ EventGraph 의 IA_Aim 처리 (실측)

실측: blueprint_query.get_graph_summary(BP_LsCharacter, "EventGraph") (node_count = 35)

BP_LsCharacter::EventGraph - IA_Aim 부분 
[EnhancedInputAction IA_Aim]
   exec_targets = [ SetGaitAndApplySettings , SetGaitAndApplySettings ]
                    └── 같은 함수를 두 개의 출력 핀에서 각각 호출

# 기존 Step 1 흐름은 그대로 유지 (실측 확인):
  Event BeginPlay → IsValid → Add Mapping Context → Link Anim Class Layers
  EnhancedInputAction IA_SwitchWeapon → Truncate → Switch on Int → Set EquippedWeapon → Link Anim Class Layers

i
측정된 사실 vs 에디터 확인 보강
  • 사실(실측): IA_Aim 노드의 두 출력 핀이 각각 SetGaitAndApplySettings 를 호출한다. 노드 2 개 모두 제목이 SetGaitAndApplySettings.
  • 에디터 확인 완료: IA_Aim 은 마우스 우클릭에 바인딩되며, 누르고 있는 동안(hold) Walking, 떼면(release) Jogging 인자로 SetGaitAndApplySettings 를 호출한다 (조준 시 걷기 속도로 감속하는 패턴). 어느 핀이 어떤 Gait 리터럴을 넘기는지는 get_graph_summary 응답(노드 제목 + exec_targets)에 없어 측정 불가였고, 이 핀-리터럴 대응은 에디터에서 직접 확인해 보강했다.

④ BPI_Animation - Character → AnimBP 통신 인터페이스

실측 cross-check: project_query.get_asset_details + blueprint_query.get_blueprint_info + get_interface_functions(interface_class="BPI_Animation_C")

BPI_Animation Blueprint Interface (신규)
부모/Script/CoreUObject.Interface 타입Interface 함수 1

함수 OnGaitChanged(NewGait : TEnumAsByte<E_Gait>), is_event = true, 출력 없음.

⑤ 메시지 송신 → 수신 (실측 cross-check)

BP_LsCharacter 는 BPI_Animation 을 구현하지 않는다 (get_interfaces = [], count 0). 대신 SetGaitAndApplySettings 안에서 Message 노드로 송신한다. ABP_Base 가 BPI_Animation 을 구현(interfaces 에 BPI_Animation_C, is_inherited=false)하고 Event OnGaitChanged 로 수신한다.

송신 (Character) → 수신 (AnimBP) 
BP_LsCharacter::SetGaitAndApplySettings
   ... Set CurrentGait ...
   [Message OnGaitChanged(Gait)]            # K2Node_Message
        comment: "ABP 에 캐릭터의 이동상태 변경을 알림"
        대상: Get Mesh → Get Anim Instance   # 메시 AnimInstance 로 전송
                       │
                       ▼  (BPI_Animation 메시지)
ABP_Base::EventGraph
   [Event OnGaitChanged(NewGait)]            # K2Node_Event, BPI 구현
        comment: "캐릭터에서 이동상태 변경시 호출됨"
        ↓
   [Set CurrentGait]                       # ABP_Base 내부 변수에 반영

# ABP_Base.EventGraph 의 옛 노드 (Event Blueprint Update Animation,
# Try Get Pawn Owner) 는 Step 1 과 동일하게 여전히 disabled
↳
왜 변수 공유가 아니라 인터페이스 메시지인가 Step 1 문서의 미해결 과제였던 "BP_LsCharacter ↔ ABP 의 상태 동기화 경로 없음" 을 Step 2 는 BP 인터페이스 메시지로 풀었다. Character 가 AnimBP 의 구체 클래스를 알 필요 없이 (메시 AnimInstance 로 메시지만 던짐), AnimBP 는 자기 시점에 OnGaitChanged 를 받아 내부 상태를 갱신한다. 결합도가 낮아 무기/캐릭터가 바뀌어도 채널이 유지된다.
