Monolith 실측 메타 / 응답 quirk 갱신

갱신 전이 룰이 이제 측정된다
Step 1 메모: "get_transitions 는 from/to/blend/duration 만, 전이 조건 식은 응답에 없음". Step 2 실측: LocomotionSM 에 대해 rule_nodes 배열을 반환했다 (TransitionResult ← 비교 ← Vector Length XY ← Get CharacterVelocity2D). 토폴로지는 측정되나 비교 상수값은 여전히 없음.
유지 IMC 키 매핑 측정 불가
IMC_ALS 가 git 변경됐는데 depends_on 에 IA_Aim 이 없다. IMC 의 키-IA 매핑은 Monolith 응답 구조상 안 보인다(nodes:[]). IA_Aim 소비는 BP_LsCharacter.EventGraph 로 cross-check 됨. 키 바인딩은 에디터 확인 대상.
cross-check 핵심 식별자 2 액션 이상
CycleLayer = get_interface_functions + get_asset_details. BPI_Animation.OnGaitChanged = get_asset_details + get_blueprint_info + get_interface_functions. 인터페이스 구현처 = get_interfaces (ABP_Base 2, BP_LsCharacter 0).
한계 핀 기본값 / Select 인덱스
노드 제목·exec_targets 까지는 측정. IA_Aim 핀→Gait 리터럴 대응, LocomotionSM 임계 상수, OnCycleUpdate 의 Select 인덱스 입력은 응답에 없어 "(추정)"/"에디터 확인" 으로 표기.

아직 빈 영역 / 다음 단계 후보

  1. Weapon ↔ AnimBP 동기화 - Gait 는 BPI 채널로 풀렸다. 같은 패턴(BPI_Animation 에 무기 변경 이벤트 추가 또는 PropertyAccess)으로 EquippedWeapon → ABP_Base.CurrentWeapon 동기화를 마저 잇는 것이 자연스러운 다음 작업.
  2. 방향성 로코모션 - 현재 Cycle 은 Walk/Jog 전방 시퀀스(*_Fwd)만 연결. 좌우/후방 또는 BlendSpace 로 확장 시 OnCycleUpdate 의 Select 가 커진다.
  3. 임계 상수 외부화 - LocomotionSM 의 속도 임계값이 전이 그래프에 하드코딩. Gait 처럼 데이터(struct/curve)로 빼면 튜닝이 쉬워진다.
  4. Step 1 로드맵의 C++ 이식 - Step 1 섹션 05 의 7 단계(ELsWeapon/ULsInputConfig → ALsCharacter → ULsAnimInstance ...)는 여전히 유효. 이번에 늘어난 E_Gait/S_GaitSetting/SetGaitAndApplySettings 도 같은 우선순위 원칙 (데이터·enum 먼저)으로 이식 대상에 합류.
★
Step 2 의 한 줄 결론 Step 1 이 "분석한 빈 골격" 의 핵심 빈칸(스레드세이프 갱신, Idle 슬롯, Character↔AnimBP 채널)을 Step 2 가 Gait 라는 구체 기능으로 채우면서, 동시에 AnimGraph 를 단일 슬롯에서 스테이트 머신으로 끌어올렸다. 데이터(enum/struct/map) - 입력(IA) - 통신(BPI) - 애니메이션(SM/Layer) 4 계층이 각자 한 가지 책임만 갖도록 분리된 점이 학습 포인트.
