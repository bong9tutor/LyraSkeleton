(1) LyraSkeleton.Target.cs - 게임 타겟

C# · LyraSkeleton.Target.cs 
using UnrealBuildTool;
using System.Collections.Generic;

public class LyraSkeletonTarget : TargetRules
{
    public LyraSkeletonTarget(TargetInfo Target) : base(Target)
    {
        Type = TargetType.Game;
        DefaultBuildSettings = BuildSettingsVersion.V6;
        IncludeOrderVersion = EngineIncludeOrderVersion.Unreal5_7;
        ExtraModuleNames.Add("LyraSkeleton");
    }
}
지시문의미
TargetType.Game최종 사용자가 실행하는 게임 빌드. 에디터 의존성 없음.
BuildSettingsVersion.V6UE 5.7 기본. 컴파일러/UBT 동작 셋(매크로 가시성, 경고 정책 등) 의 버전.
EngineIncludeOrderVersion.Unreal5_7IWYU 기준 include 정렬·deprecate 규칙. 새 코드도 이 기준을 따라야 경고가 없습니다.
ExtraModuleNames.Add("LyraSkeleton")이 타겟이 끌어올 모듈. 새 모듈을 추가하면 여기에 함께 등록.

(2) LyraSkeletonEditor.Target.cs - 에디터 타겟

위와 거의 동일한 구조에 Type = TargetType.Editor 만 다릅니다. 학습 단계에서는 이쪽만 빌드하면 충분합니다.

U
두 타겟이 왜 따로 있나 에디터 타겟은 UnrealEd, ToolMenus, EditorStyle 등의 에디터 전용 모듈에 접근할 수 있습니다. 게임 타겟은 그 의존이 없는 깨끗한 상태로 빌드되어 패키지에 들어갑니다.

(3) LyraSkeleton.Build.cs - 모듈 의존성

C# · LyraSkeleton/LyraSkeleton.Build.cs 
public class LyraSkeleton : ModuleRules
{
    public LyraSkeleton(ReadOnlyTargetRules Target) : base(Target)
    {
        PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;

        PublicDependencyModuleNames.AddRange(new string[] {
            "Core",
            "CoreUObject",
            "Engine",
            "InputCore",
            "EnhancedInput"     # ← 이게 핵심
        });

        PrivateDependencyModuleNames.AddRange(new string[] {  });
    }
}

의존 모듈 4 + 1 의 의미

Core
UE 의 기본 타입(FString, TArray, 로깅 등). 모든 모듈의 1 번 의존.
CoreUObject
UObject/UClass/리플렉션. UE 의 객체 시스템 본진.
Engine
AActor, UWorld, 컴포넌트 시스템, 게임플레이 프레임워크.
InputCore
키 코드/입력 추상화. Enhanced Input 의 하위 계층.
EnhancedInput
본 프로젝트의 입력은 모두 Enhanced Input. BP_LsCharacter 의 BeginPlay 에서 IMC_ALS 를 Subsystem 에 Add 한다.

왜 EnhancedInput 이 Public 의존인가

i
앞으로 새로 추가될 ALsCharacter 같은 헤더가 공개적으로 UInputMappingContext*, UInputAction* 매개변수를 노출할 가능성이 높기 때문입니다. 헤더에 등장하는 타입이 속한 모듈은 Public, .cpp 안에서만 쓰는 모듈은 Private 으로 두는 것이 모듈 의존성 정리의 1 차 원칙. 전체 표준은 docs/CodingStandard.md 의 16 절 참조.

PCH 정책

PCH Mode 
PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;

각 모듈의 자기 PCH 가 있으면 그것을 쓰고, 없으면 엔진의 Shared PCH 를 씁니다. "PCH 가 알아서 다 끌어와 주겠지" 라는 가정에 기대지 않고, 새 헤더에서는 IWYU 원칙에 따라 필요한 헤더를 명시적으로 include 하세요.

(4) LyraSkeleton.cpp - 모듈 진입점

C++ · LyraSkeleton.cpp 
// Copyright Epic Games, Inc. All Rights Reserved.

#include "LyraSkeleton.h"
#include "Modules/ModuleManager.h"

IMPLEMENT_PRIMARY_GAME_MODULE( FDefaultGameModuleImpl, LyraSkeleton, "LyraSkeleton" );

이 매크로 한 줄이 "LyraSkeleton 이 이 프로젝트의 주 게임 모듈" 임을 UBT/엔진에 등록합니다. 모듈 시작·종료 시점에 후크가 필요해지면 FDefaultGameModuleImpl 대신 직접 만든 FLyraSkeletonModule(IModuleInterface 파생) 로 교체하게 됩니다 - 지금은 그럴 필요가 없는 상태.

새 클래스 추가 워크플로 (예고)

  1. 에디터에서 Tools → New C++ Class 또는 직접 파일 생성 후 GenerateProjectFiles.bat 재실행.
  2. 접두사 정책 적용: U/A/F/E/I/S + Ls + 이름 (예: ULsAnimInstance, ALsCharacter).
  3. 모듈 외부에서 참조될 헤더면 LYRASKELETON_API export 매크로를 단다.
  4. LyraSkeletonEditor 타겟을 빌드. UHT 가 generated.h 를 갱신.
  5. 에디터에서 해당 클래스로부터 BP 를 만들거나, 기존 BP 의 ReparentBlueprint 로 부모를 교체.
