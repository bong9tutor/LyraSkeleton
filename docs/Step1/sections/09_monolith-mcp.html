Monolith MCP 자동화 범위와 갭

Plugins/Monolith/ 의 Monolith MCP (tumourlove/monolith v0.14.10) 가 본 프로젝트 자산을 분석할 때의 자동화 가능 영역, 한계, 권장 호출 순서, 그리고 실제로 확인된 응답 버그 1 건 정리.

Monolith 기본 정보

항목값
저장소tumourlove/monolith
라이선스MIT
지원 UE 버전UE 5.7+
본 프로젝트 핀v0.14.10
총 액션 수1,220
네임스페이스 수15

에디터 in-process 로 동작하는 MCP 서버입니다. UnrealEditor.exe 가 켜져 있을 때만 응답합니다. 클라이언트(Claude) 는 .mcp.json 에 등록된 프록시를 통해 액션을 호출합니다.

자동화가 강한 부분 (≥90%)

① BP 클래스 골격

부모 클래스, 컴포넌트 트리(트랜스폼 포함), 변수 9 컬럼, 함수 시그니처(로컬 변수 포함), CDO 디폴트, 구현 인터페이스.

② EventGraph 의사코드

connected_to=["NodeName.PinName"] 가 핀 이름까지 보존하므로 의사코드 재구성이 환각 없이 가능.

③ State Machine 토폴로지

State 목록과 transition(from/to/blend_mode/duration). Mermaid stateDiagram-v2 로 즉시 변환.

④ 의존성 그래프

project_query.find_references 가 hard/soft 양방향 참조를 즉시 제공.

⑤ Linked Anim Layer 매핑

ALI 함수 ↔ 무기 상태별 ABP 슬롯 매핑이 animation_query.get_linked_layers 한 호출로 나옴.

⑥ BP 간 diff

compare_blueprints 가 변수/컴포넌트/함수/그래프별 added/removed/modified 를 emit.

자동화가 약한 부분 (사람 보충 필요)

!
이 영역에서는 LLM 의 추측을 절대 신뢰하지 마세요. 직접 에디터에서 확인하거나, 스크린샷/UE Python 보조가 필요합니다.
  1. AnimGraph 의 핀 흐름 - Output Pose 까지의 연결이 응답에 빠집니다. get_blend_nodes 는 핀별 connections 를 개수 로만 줍니다.
  2. State Transition 의 rule graph - 전이 조건의 bool 식(예: Speed > 50 일 때 Idle → Walk) 이 통째로 빠집니다.
  3. State 안의 애니메이션 자산 매핑 - 어떤 state 에 어떤 BlendSpace/Sequence 가 물려 있는지가 자동 매핑되지 않습니다.
  4. 그래프 코멘트 박스 그루핑 - 영역을 나누는 코멘트 박스 메타가 emit 되지 않습니다.
  5. IMC 의 키 매핑 - 인덱서 자체가 IMC 를 무시합니다. IMC_ALS 의 "WASD → IA_Move" 정보는 0%.
  6. 노드 색상/카테고리 시각 단서 - SerializeNode 에 없습니다.
  7. 의도/디자인 컨텍스트 - "왜 이런 구조인가" 는 어떤 도구로도 자동화 불가, 항상 사람 보충.

자산별 자동화 비율 (요약)

BP 클래스 골격 90%+
자동화 강

EventGraph 의사코드, 의존성, State Machine 토폴로지까지 거의 사람 검수 없이 마크다운으로 생성 가능.

  • 사람 보충: 의도 설명 1-2 단락
AnimGraph 흐름 30~50%
중간

핀별 connections 가 개수로만 나오고 전이 조건 rule graph 가 응답에서 빠짐. 의미적 흐름 자동화는 부족.

  • 전이 조건: 에디터에서 직접 확인
  • 핀 연결: 스크린샷 또는 텍스트로 보충
IMC 키 매핑 0%
자동화 불가

인덱서 자체가 IMC 를 무시. IMC_ALS 의 "WASD → IA_Move" 매핑은 Monolith 단독으로 0%.

  • 대안: UE Python unreal.EnhancedInputLibrary 또는 수동 작성
코멘트 박스 그루핑 0%
자동화 불가

학습 BP 가 영역을 나누는 코멘트 박스(UEdGraphNode_Comment) 의 영역 메타가 emit 되지 않음.

  • 사람이 영역 구분을 추가로 기술해야 함

권장 호출 순서

  1. list_graphs - 그래프 목록만 가져옴 (가벼움).
  2. 그래프마다 get_graph_summary - 수 KB 수준의 요약.
  3. 흥미로운 노드만 get_node_details.
  4. get_graph_data 풀 덤프는 명시적으로 필요할 때만 (한 BP 가 100KB+ 로 부풀 수 있음).
i
토큰 예산의 현실 Monolith README 의 "~10 KB (summary)" vs "~172 KB (get_graph_data)" 는 GASP 수준의 복합 그래프 한 개 기준입니다. BP_LsCharacter 의 EventGraph 도 ALS 캐릭터 복잡도라면 100KB 대 가능.

실측 사례: 응답 자체에 오타가 섞일 수 있다 (cross-check 필수)

!
본 문서 작성 중 확인된 응답 버그 animation_query.get_abp_info("/Game/ALS/Characters/ABP_Base") 의 graphs 배열이 ["AnimGraph", "BlueprintThreadSafeUpdateAnimation", "GetChracterMovement", "EventGraph"] 로 반환되었습니다. 그러나 같은 자산의 blueprint_query.get_functions 응답은 "name":"GetCharacterMovement" (정상) 였고, get_graph_summary("GetChracterMovement") 를 시도하면 "Graph not found" 에러가 발생합니다. 정상 이름인 "GetCharacterMovement" 로 호출해야 5 개 노드가 정상 반환됩니다.

즉 get_abp_info 응답 한 곳에서만 그래프 이름이 오표기된 Monolith MCP 자체의 응답 버그입니다. 학습 프로젝트의 자산 이름에는 오타가 없습니다.
i
운용 원칙
  • 한 액션의 단일 응답을 100% 신뢰하지 않음. 핵심 식별자(이름·경로) 는 다른 액션의 응답과 대조.
  • 그래프 이름의 1 차 자료는 blueprint_query.get_functions 또는 list_graphs. animation_query.get_abp_info 의 graphs 배열은 보조.
  • 자동 산출 문서에 자산명을 그대로 박아 넣기 전 재호출로 검증.

안전 가드

Monolith 의 BP/Material/Animation 모듈은 풀 CRUD 를 지원한다(임의 쓰기 가능). 분석 세션이 의도치 않게 자산을 수정할 위험이 있으므로 다음 절차를 권장한다.

  • Git 트리가 깨끗한 상태에서 세션 시작.
  • 첫 세션은 blueprint_query.*, animation_query.*, project_query.* 의 read 액션만 사용.
  • 매 세션 종료 후 git status/git diff 로 Content/ 변경 확인.
  • 변경이 발견되면 stash 또는 reset 검토.
  • allowlist/denylist 옵션을 확정한 뒤 read 전용 프로파일 분리.
