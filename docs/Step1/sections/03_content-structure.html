Content/ALS 자산 맵

Content/ALS/ 아래 13 개 자산의 위치·역할·의존성 정리. GameMode → Pawn → Mesh → AnimBP 체인과 무기 상태별 자식 ABP 슬롯이 어떻게 묶이는지를 도식화한다.

"Ls" 프로젝트 태그 정책

i
게임플레이 BP 에만 프로젝트 태그 Ls 가 붙습니다 (BP_LsCharacter, BP_LsGameMode). 반면 보조 자산 (ABP_*, ALI_*, IMC_*, IA_*, E_*, L_*) 에는 태그를 붙이지 않습니다. 새 자산을 만들 때 이 패턴을 깨지 마세요.

  → Inertialization 으로 부드럽게 블렌딩

(1) BP_LsGameMode - 기본 맵의 GameMode

L_Start 의 World Settings → GameMode Override 에서 지정되어 있습니다(혹은 Project Settings 의 Default GameMode). 이 GameMode 가 DefaultPawnClass 를 BP_LsCharacter 로 두어, 플레이어가 스폰될 때 어떤 캐릭터가 될지를 결정합니다.

왜 BP 인가

현재는 단순한 캐스팅과 클래스 지정뿐이라 BP 만으로 충분합니다. 학습 후반에 매치플로가 늘면 C++ ALsGameMode 로 이식 후보.

학습 포인트

GameMode 가 "누가 누구를 스폰하는가" 의 책임을 가진다는 개념 자체.

(2) BP_LsCharacter - 메인 Pawn

이 자산이 본 문서에서 가장 자주 등장한다. 다음 책임들이 모여 있다.

  • 입력 매핑 컨텍스트 등록 - BeginPlay 에서 EnhancedInputLocalPlayerSubsystem 에 IMC_ALS 를 Add
  • 입력 이벤트 처리 - EventGraph 에 직접 배치된 EnhancedInputAction IA_Move/IA_Look/IA_SwitchWeapon 노드 (별도의 SetupPlayerInputComponent 함수 없음)
  • 현재 무기 상태 보관 - 변수 EquippedWeapon (byte, default = UnArmed)
  • 레이어 전환 호출 - 무기 전환 시 Mesh->LinkAnimClassLayers(ABP_Pistol::Class 또는 ABP_UnArmed::Class)
U
실측 BP 추가 컴포넌트 BP_LsCharacter 가 BP 단에서 추가한 컴포넌트는 SpringArm + Camera 2 개(3 인칭 카메라 셋업). 그 외 CollisionCylinder/Arrow/CharMoveComp/CharacterMesh0 는 ACharacter 부모에서 상속된 native 컴포넌트.
★
C++ 이식 시 자연스러운 분리 Step 2 이후 이식하게 되면, 위 4 가지 책임은 보통 다음으로 나뉩니다.
  • 이동/카메라 → ALsCharacter
  • 무기 상태 모델 → ULsWeaponComponent
  • 입력 매핑 등록/바인딩 → ALsPlayerController
  • 애니메이션 데이터 계산 → ULsAnimInstance

(3) ABP_Base / ABP_Layers / ABP_Pistol / ABP_UnArmed

AnimBP 4 종이 "베이스 + 무기 상태별 레이어" 패턴을 만든다. 상세 동작은 섹션 04 (애니메이션 레이어 시스템) 참조. 여기서는 자산 목록과 한 줄 책임만 짚는다.

ABP_Base 메인
부모AnimInstance implements ALI_Animation

캐릭터 메시의 메인 AnimBP. AnimGraph 에 LinkedAnimLayer(IdleLayer) + Inertialization + Output Pose.

ABP_Layers 부모 클래스
부모AnimInstance implements ALI_Animation

ABP_Pistol/ABP_UnArmed 의 부모 AnimBP 클래스. OnIdleUpdate 함수가 자식들이 공유하는 베이스 포즈 갱신 슬롯.

ABP_Pistol 자식
부모ABP_Layers 인터페이스부모에서 상속

권총 상태에서 끼워지는 자식 ABP. 인터페이스 구현은 부모에서 상속.

ABP_UnArmed 자식
부모ABP_Layers 인터페이스부모에서 상속

비무장 상태에서 끼워지는 자식 ABP. 인터페이스 구현은 부모에서 상속.

i
인터페이스 구현은 부모-자식 상속 체인을 따른다 Monolith MCP 실측: ABP_Pistol/ABP_UnArmed 의 interfaces 필드는 빈 배열입니다. 실제로 ALI_Animation 을 선언적으로 구현 하는 곳은 ABP_Base 와 ABP_Layers 입니다. 무기별 자식 ABP 는 ABP_Layers 를 상속받아 인터페이스 함수만 override 합니다.

(4) ALI_Animation - Anim Layer Interface

ABP_Base 가 "이 슬롯의 포즈를 채워줄 외부 ABP" 를 부르는 약속(인터페이스) 입니다. ABP_Pistol 과 ABP_UnArmed 가 같은 인터페이스를 구현하기 때문에, 무기 상태가 바뀌어도 ABP_Base 의 그래프는 그대로 둔 채 안쪽 레이어만 갈아낄 수 있습니다.

↳
학습 가치 "같은 골격, 다른 포즈" 를 Branch 노드 도배 없이 깔끔히 다루는 Lyra 의 핵심 패턴입니다. 새 무기를 추가하고 싶다면 같은 ALI_Animation 인터페이스를 구현하는 새 ABP 한 개를 만들고, BP_LsCharacter 의 상태 전환 분기에 한 줄을 더하면 끝입니다.

(5) Inputs - IMC_ALS 와 3 개의 IA

Enhanced Input 의 표준 패턴입니다. IMC_ALS 는 키 → IA 매핑의 묶음, IA 는 입력 의미의 단위. IMC_ALS 는 의존 IA 3 종 (IA_Move Axis2D, IA_Look Axis2D, IA_SwitchWeapon Axis1D) 을 묶는다. 키-IA 매핑은 Monolith 응답에 없어 에디터에서 직접 확인 필요.

(6) Enums/E_Weapon - 무기 식별 enum

현재 무기를 식별하는 키. BP_LsCharacter 의 변수가 이 enum 으로 들고 있고, ABP_Base 가 이 값을 보고 어떤 레이어를 끼울지 결정합니다.

i
C++ 로 이식 시 형태 
UENUM(BlueprintType) enum class ELsWeapon : uint8 { None, Pistol };
docs/CodingStandard.md 의 enum 정책 (enum class : uint8, UENUM(BlueprintType)) 을 따른다.

(7) Maps/L_Start.umap

유일한 맵입니다. DefaultEngine.ini 에서 GameDefaultMap 과 EditorStartupMap 모두 이 맵으로 지정되어 있어, 에디터를 켜면 자동으로 열립니다.

확장 시 손대는 자산

자산 의존 체인을 바탕으로 한 영향 범위 분석.

새 무기 추가 (예: Rifle)
  1. E_Weapon 에 Rifle 항목 추가
  2. ABP_Rifle 신규 생성 (부모 = ABP_Layers, 인터페이스는 부모에서 상속)
  3. BP_LsCharacter 의 Switch on Int 에 새 case 추가, LinkAnimClassLayers(ABP_Rifle_C) 호출
  4. (선택) IA_Fire 추가 후 IMC_ALS 매핑
새 맵 추가 (예: 사격장)
  1. Content/ALS/Maps/L_Range.umap 생성
  2. World Settings 의 GameModeOverride 를 BP_LsGameMode 로 설정
  3. 진입점 교체 시 DefaultEngine.ini 의 GameDefaultMap 갱신
