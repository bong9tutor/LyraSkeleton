이식 우선순위와 비어있는 슬롯

현재 BP/AnimBP 에 존재하지만 비어 있는 슬롯의 명세와, BP → C++ 이식 7 단계 우선순위 정리.

비어있는 슬롯 명세 (실측)

Monolith 실측으로 확인된 빈 슬롯 목록. 이미 정의되어 있으나 로직이 없는 항목들이다.

ABP_Base.BlueprintThreadSafeUpdateAnimation 슬롯
시그니처(float DeltaTime) 현재 비어있음

FunctionEntry 1 개만 있고 실 로직 없음.

  • 속도/회전/가속도 캐싱
  • EquippedWeapon → CurrentWeapon 동기화
ABP_Layers.OnIdleUpdate Anim Layer Update
시그니처(Context, Node) 노드 0 개

IdleLayer 슬롯에 묶이는 갱신 함수. 부모가 들고 있어 자식이 공유.

  • AnimNodeReference 를 통한 idle 시퀀스 갱신 (속도 조건부)
ABP_Layers.AnimGraph 출력 그래프
Output Pose 1 개뿐

실 포즈 노드 연결이 없는 빈 그래프.

  • MM_Unarmed_Idle_Ready 를 실제 Output Pose 에 연결
ABP_Pistol / UnArmed EventGraph 자식 ABP
모든 노드 disabled

자식 ABP 들이 본질적으로 비어 있음.

  • 자식별 override 가 필요한 경우만 활성화 (대부분 부모로 충분)
ABP_Base.CurrentWeapon ↔ BP_LsCharacter.EquippedWeapon 동기화 채널
미연결

두 변수가 동일 의미(byte 무기 enum)이나 현재 어느 쪽으로도 흐름이 없다. 무기 전환 시 동기화 경로가 필요하다.

  • PropertyAccess (BP_LsCharacter.EquippedWeapon → ABP_Base.CurrentWeapon) 가 자연스러움
  • 또는 새 커스텀 이벤트로 push (과거 SwitchWeapon_1 패턴 재도입)
BP_LsCharacter Switch on Int 분기 보강
case 0 없음

case 1/2 만 다뤄 case 0 입력은 무시. 입력 매핑 의도 명확화 필요.

  • 의도된 입력값(휠 +1/-1, 키 1/2 등) 을 IMC 에서 확인 후 case 보정
BP_LsCharacter Tick / Overlap 기본 이벤트
두 노드 disabled 학습 단계에선 OK

Event Tick 과 Event ActorBeginOverlap 두 노드가 모두 disabled 상태.

  • 필요한 시점에만 활성화. 학습 단계에선 비워두는 게 정답.

이식 우선순위 - 의존성이 짧은 것부터

원칙: 데이터/열거형 등 의존성이 짧은 것부터 옮기고, 액션/바인딩 코드는 나중. BP 가 C++ 클래스에 의존하기는 쉬우나 반대 방향은 GC/리로드 위험이 크다.

순서이식 대상새 C++ 타입 (제안)대체될 BP
① 데이터·Enum무기 식별 enumELsWeapon (헤더 only)E_Weapon 의 참조를 새 enum 으로 마이그레이션
② 입력 설정입력 자산 묶음ULsInputConfig (DataAsset)BP_LsCharacter 가 들고 있던 IA 참조들을 외부화

④ AnimInstance입력 의도·속도 계산ULsAnimInstanceABP_Base 의 부모를 교체

이식 = 책임 분해 BP 한 자산의 책임이 그대로 한 C++ 클래스로 옮겨가지 않는다. 보통 1 → 3 으로 쪼개진다. 예: BP_LsCharacter → ALsCharacter + ULsWeaponComponent + ALsPlayerController.

Step 별 산출물 (제안)

Step 2 Enum + 데이터

ELsWeapon, ULsInputConfig 생성. BP 가 새 타입을 참조하도록 마이그레이션.

키 토픽: UENUM(BlueprintType), DataAsset, BP 참조 마이그레이션.

Step 3 ALsCharacter

BP_LsCharacter 의 부모를 ALsCharacter 로 교체. 이동/카메라 먼저 이식.

키 토픽: ReparentBlueprint, BeginPlay vs SetupPlayerInputComponent.

Step 4 ULsAnimInstance

ABP_Base 의 부모를 ULsAnimInstance 로. BlueprintThreadSafeUpdateAnimation 그래프의 로직을 C++ NativeThreadSafeUpdateAnimation 으로 이전.

키 토픽: 게임 스레드 vs 워커 스레드, UPROPERTY 노출, FAnimInstanceProxy.

Step 5 ULsWeaponComponent

무기 상태/전환/레이어 link 를 컴포넌트로 추출. BP_LsCharacter 가 컴포넌트를 호스트.

키 토픽: 컴포넌트 추상화, LinkAnimClassLayers 호출 위치.

Step 6 ALsPlayerController

입력 매핑 등록/바인딩을 캐릭터에서 컨트롤러로 이관. Pawn 변경 후에도 입력 컨텍스트 유지.

키 토픽: 입력 권위(authority) 위치, 매핑 컨텍스트 우선순위.

Step 7 ALsGameMode

BP_LsGameMode 의 부모 교체. 매치 시작/재시작/기본 Pawn 클래스 결정 책임.

키 토픽: GameMode vs GameState 책임 분리.

보조 인프라 (이식 전 도입 후보)

+ Automation Test
IMPLEMENT_SIMPLE_AUTOMATION_TEST 1 개 이상 추가. 이식 함수의 회귀 테스트 기반.
+ 로그 카테고리 분리
LogLsCharacter, LogLsAnim, LogLsWeapon 등. 디버깅 비용 절감.

자주 보는 값(속도, 입력 의도)을 SCOPE_CYCLE_COUNTER / STAT_DRAWING.
+ CI 빌드
GitHub Actions/Jenkins 로 LyraSkeletonEditor 빌드 자동화. PR 회귀 차단.

이식 작업 원칙

  1. 한 번에 한 책임 - BP_LsCharacter 의 입력·이동·무기·애니메이션을 한꺼번에 옮기지 않는다.
  2. ReparentBlueprint 후 즉시 검증 - 부모 교체는 사고가 잦은 단계. 매 단계마다 PIE 1 회 + 에디터 컴파일 확인.
  3. Ls 접두사 유지 - docs/CodingStandard.md 의 2 절 정책. LYRASKELETON_API 도 빠뜨리지 않는다.
  4. 로그 흔적 - UE_LOG(LogLsXxx, ...) 로 이식 중 멈춘 위치를 추적 가능하게 한다.
