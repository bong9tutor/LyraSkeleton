SECTION 02 · 환경 구성

빌드와 실행 워크플로

UE 5.7 표준 명령 시퀀스. 솔루션 재생성 → 에디터 빌드 → 에디터 실행 → (선택) 패키징. 명령은 CLAUDE.md 의 빌드 섹션과 동일하다.

0. 사전 준비 - UE 5.7 설치 경로 변수

UE 설치 경로가 사람마다 다르므로 본 문서에서는 $UE 라는 PowerShell 변수에 잡아 두고 이후 모든 명령에서 그 변수를 참조한다. 기본 경로는 C:\Program Files\Epic Games\UE_5.7.

PowerShell 
PS> $UE = "C:\Program Files\Epic Games\UE_5.7"
PS> Test-Path "$UE\Engine\Build\BatchFiles\Build.bat"
True
i
경로가 다를 때 Epic Games Launcher 의 Library → Engine Versions → 5.7 옆 아래 화살표에서 "Open Folder" 를 눌러보면 실제 설치 경로가 뜹니다. 이 경로를 변수에 넣으세요.
본 문서의 모든 명령은 $UE 변수를 기준으로 한다.

1. 솔루션 파일 재생성 (Generate Project Files)

.sln(Visual Studio) 또는 .uproject 인덱스(Rider) 가 깨졌거나, 새 C++ 클래스를 추가한 직후에는 솔루션을 다시 만들어 줘야 IDE 가 최신 모듈 구조를 인식합니다.

PowerShell · Generate Project Files 
PS> & "$UE\Engine\Build\BatchFiles\GenerateProjectFiles.bat" `
        -Project="D:\Projects\Testing\LyraSkeleton\LyraSkeleton.uproject" `
        -game -rocket
-Project=
.uproject 절대 경로. 공백이 있으면 따옴표 필수.
-game
게임 프로젝트로 인식. 엔진 솔루션과 섞이지 않게 함.
-rocket
Epic Launcher 로 설치된 (= Installed Build) 엔진을 가리킬 때 쓰는 플래그.

2. 에디터 타겟 빌드 (Development Editor)

C++ 코드를 한 줄도 안 만진 시점이라도, 처음 클론했을 때는 에디터 타겟을 한 번 빌드해 두는 것이 안전합니다. UHT(Unreal Header Tool) 가 리플렉션 코드를 갱신하고, 모듈이 사용 가능한 상태가 됩니다.

PowerShell · Build Editor Target 
PS> & "$UE\Engine\Build\BatchFiles\Build.bat" `
        LyraSkeletonEditor Win64 Development `
        -Project="D:\Projects\Testing\LyraSkeleton\LyraSkeleton.uproject" `
        -WaitMutex
인자의미
LyraSkeletonEditor빌드할 타겟 이름. Source/LyraSkeletonEditor.Target.cs 와 일치.
Win64플랫폼.
Development구성(Configuration). 학습/개발용은 거의 항상 이 값.
-WaitMutex다른 UE 빌드가 동시에 도는 경우 충돌 없이 대기.
↳
빌드 구성 5 종 Debug · DebugGame · Development · Test · Shipping. 학습 단계에서는 Development 만 쓰면 충분합니다. check() / ensure() 등 어서션 동작이 구성마다 달라지는데 이는 섹션 08 (코딩 표준) 에서 다룹니다.

3. 에디터 실행

에디터 빌드가 끝났다면 UnrealEditor.exe 에 프로젝트 경로를 넘겨 직접 켭니다. (Epic Launcher 의 "Open" 버튼도 결국 같은 명령을 호출합니다.)

PowerShell · Launch Editor 
PS> & "$UE\Engine\Binaries\Win64\UnrealEditor.exe" `
        "D:\Projects\Testing\LyraSkeleton\LyraSkeleton.uproject"
i
첫 실행은 셰이더 컴파일 때문에 오래 걸립니다. Lumen + Substrate + SM6 + Ray Tracing 이 모두 켜져 있어 셰이더 풀이 크기 때문입니다. 두 번째 부터는 캐시(DerivedDataCache) 가 채워져 짧아집니다. 이 옵션을 끄지 말아야 하는 이유는 섹션 03 참조.

4. (선택) 패키징 - 배포용 빌드

학습 단계에서 자주 쓰지는 않지만, 외부에 보여줘야 하거나 빌드 사이클을 시험할 때 RunUAT.bat 의 BuildCookRun 으로 한 번에 패키지를 만들 수 있습니다.

PowerShell · BuildCookRun 
PS> & "$UE\Engine\Build\BatchFiles\RunUAT.bat" BuildCookRun `
        -project="D:\Projects\Testing\LyraSkeleton\LyraSkeleton.uproject" `
        -platform=Win64 -clientconfig=Development `
        -build -cook -stage -pak -archive `
        -archivedirectory="D:\Projects\Testing\LyraSkeleton\Build"

-build

패키지에 들어갈 바이너리(LyraSkeleton 게임 타겟) 를 빌드.

-cook

에셋을 타겟 플랫폼용 cooked 포맷으로 변환.

-stage / -pak

스테이징 폴더에 모은 뒤 .pak 한 덩어리로 묶음.

-archive

-archivedirectory 로 지정한 경로에 최종 결과를 복사.

흔히 만나는 함정

!
"Could not find the source directory" -Project= 의 경로가 잘못 됐거나 따옴표가 안 닫혔을 때 나옵니다. 경로 끝에 공백/ 한국어 폴더가 없는지 다시 확인하세요.
!
"Mutex 잠금" / 동시 빌드 충돌 IDE(Rider/Visual Studio) 의 백그라운드 빌드가 동시에 돌면 Build.bat 이 잠금에 걸립니다. IDE 의 빌드를 멈추거나 -WaitMutex 인자로 기다리게 하세요.
!
"Hot Reload failed" / 모듈 리로드 실패 에디터를 켠 상태에서 코드를 만지고 다시 빌드하면 가끔 발생합니다. 에디터를 종료한 뒤 빌드 하거나, 에디터의 Live Coding (Ctrl+Alt+F11) 을 사용하세요.

참고: 자동화 테스트와 정적 분석

i
본 프로젝트에는 자동화 테스트 / lint / 정적 분석이 구성되어 있지 않다. Automation 모듈과 IMPLEMENT_SIMPLE_AUTOMATION_TEST 도입은 향후 작업 후보 (섹션 10 참조).
