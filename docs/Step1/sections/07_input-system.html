Enhanced Input 입력 흐름

IMC_ALS + 3 개의 IA (IA_Move, IA_Look, IA_SwitchWeapon) 와 BP_LsCharacter EventGraph 의 입력 처리 흐름 분석.

Enhanced Input 시스템 특성

UE 5.1 이후 신규 프로젝트의 입력 표준. 기존 Axis/Action Mapping(legacy) 대비 차이:

컨텍스트 분리
게임플레이/메뉴 매핑을 IMC 단위로 분리해 런타임 push/pop.
Trigger / Modifier
Hold/Tap/DeadZone 같은 입력 의미를 자산 수준에서 정의.
타입 안전
IA 가 Axis1D/Axis2D/Bool 등 값 타입을 갖고 핸들러가 그대로 받음.
Lyra 호환
Lyra 가 동일 시스템 사용. 자산 패턴이 그대로 확장 가능.

DefaultInput.ini 에서 보이는 한 줄

Config/DefaultInput.ini · [/Script/Engine.InputSettings] 
DefaultPlayerInputClass=/Script/EnhancedInput.EnhancedPlayerInput
DefaultInputComponentClass=/Script/EnhancedInput.EnhancedInputComponent

플레이어 컨트롤러가 사용하는 입력 클래스가 Enhanced 버전 으로 못 박혀 있습니다. 이 두 줄이 "프로젝트 전반의 입력은 Enhanced Input 으로 통일" 의 효력입니다.

구성 자산 5 개

출처: project_query.get_asset_details.

IMC_ALS Mapping Context
타입InputMappingContext 의존 IA 3 개

키 → IA 매핑 묶음. BP_LsCharacter::BeginPlay 에서 Subsystem 에 Add 되어 활성화.

  • 의존: IA_Move, IA_Look, IA_SwitchWeapon
  • 키 ↔ IA 매핑 내용은 Monolith 응답에 없음 (에디터에서 직접 확인 필요)
IA_Move InputAction
Axis2D 트리거없음 모디파이어없음

이동 입력. 핸들러에서 Get Control Rotation 의 Forward/Right Vector 와 곱해 Add Movement Input 으로 전달.

IA_Look InputAction
Axis2D 트리거없음 모디파이어없음

시점 입력. Break Vector 2D 후 Add Controller Yaw Input + Add Controller Pitch Input.

IA_SwitchWeapon InputAction
Axis1D 트리거없음 모디파이어없음

무기 토글. EventGraph 에서 Started 핀 → Truncate → Switch on Int 로 분기 (휠/스크롤 형태로 추정).

  • Bool 이 아니라 Axis1D 임에 주의
  • 분기는 case 1 (UnArmed), case 2 (Pistol) 만 - case 0 무시
E_Weapon UserDefinedEnum
UnArmed=0 Pistol=1

입력 자산은 아니지만, 무기 상태 변수 EquippedWeapon(BP_LsCharacter) 과 CurrentWeapon(ABP_Base) 의 기반 enum.

!
IA_SwitchWeapon 은 Bool 이 아니라 Axis1D IA_SwitchWeapon 의 value_type 은 EInputActionValueType::Axis1D. BP_LsCharacter EventGraph 가 그 값을 Truncate 로 정수화한 뒤 Switch on Int 로 분기하므로, 단일 키 토글보다는 휠/방향키 같은 연속 1D 입력을 가정한 설계로 보인다.

전체 입력 흐름

Input Flow 
키 입력 (예: W)
   ↓
IMC_ALS 의 매핑 (W → IA_Move, Modifier: SwizzleAxis(Y))
   ↓
EnhancedPlayerInput 가 IA_Move 트리거 + Axis2D 값 (Y=1) 생성
   ↓
BP_LsCharacter 의 BindAction(IA_Move, Triggered) 핸들러
   ↓
캐릭터의 AddMovementInput / 카메라 회전 / 무기 전환

BP_LsCharacter 측 실제 등록 패턴 (실측)

현재 BP_LsCharacter 에는 커스텀 함수가 없습니다 (오직 UserConstructionScript 1 개). 모든 입력 처리가 EventGraph 한 곳에 노드로 풀어져 있습니다. Enhanced Input 의 BP 노드 인 EnhancedInputAction IA_* 가 별도 BindAction 호출 없이 자동으로 이벤트 핀을 제공하기 때문입니다.

① BeginPlay - IMC 등록 + 초기 ABP 레이어 연결 
// 실측 EventGraph 흐름 (node_id 와 핀 연결까지 확인)
Event BeginPlay
  → Get Player Controller → IsValid? (Branch)
  → Get EnhancedInputLocalPlayerSubsystem from PC
  → Add Mapping Context(
        MappingContext = IMC_ALS,
        Priority = 0,
        Options = (bIgnoreAllPressedKeysUntilRelease=True,
                   bForceImmediately=False,
                   bNotifyUserSettings=False)
    )
  → Get Mesh (CharacterMesh0)
  → Link Anim Class Layers(InClass = ABP_UnArmed_C)   # 초기 상태 = 비무장
i
bIgnoreAllPressedKeysUntilRelease=True 가 켜져 있는 이유 IMC 가 추가되는 순간 이미 눌려 있던 키들이 즉시 입력으로 발화하는 것을 막아주는 옵션입니다. 매핑 컨텍스트를 런타임에 추가/제거할 때 의도치 않은 발화 (예: PIE 시작 시 마우스 우클릭이 눌려 있던 상태) 를 막아 흔히 켭니다.
② EventGraph 의 EnhancedInputAction 노드들 (BindAction 함수 없음) 
EnhancedInputAction IA_Move     [Triggered]
   ActionValue (Vector2D)
       → Break Vector 2D
       → Add Movement Input × 2  # Forward 와 Right 각각
   # Get Control Rotation 의 Forward/Right Vector 를 방향 벡터로 사용

EnhancedInputAction IA_Look     [Triggered]
   ActionValue (Vector2D)
       → Break Vector 2D
       → Add Controller Yaw Input   (X)
       → Add Controller Pitch Input (Y)

EnhancedInputAction IA_SwitchWeapon [Started]   # Triggered 가 아님
   ActionValue (double = Axis1D)
       → Truncate (KismetMathLibrary.FTrunc) → int
       → Switch on Int
            ├── case 1: Set EquippedWeapon=NewEnumerator0(UnArmed)
            │           → LinkAnimClassLayers(ABP_UnArmed_C)
            ├── case 2: Set EquippedWeapon=NewEnumerator1(Pistol)
            │           → LinkAnimClassLayers(ABP_Pistol_C)
            └── 그 외 : 분기 없음
!
SwitchWeapon 분기에 case 0 이 없다 Switch on Int 가 case 1/2 만 다루기 때문에 입력값이 0 일 때는 아무 일도 일어나지 않습니다. Axis1D 입력의 부호(+1/-1) 나 누적값(1, 2) 으로 무기를 토글하는 패턴이며, 단일 키의 on/off 가 아닙니다. Step 2 이후에 마우스 휠 또는 숫자 키 ↔ 분기 값 매핑을 IMC 에서 어떻게 잡아두었는지 확인하고, 더 직관적인 토글로 리팩토링하는 것이 다음 학습 과제입니다.
i
BP 와 C++ 의 차이 BP 에서는 EnhancedInputAction 노드가 자체적으로 핀 (Triggered, Started, Completed, Ongoing, Canceled) 을 제공하므로 별도의 BindAction 호출이 필요 없습니다. C++ 로 이식할 때는 SetupPlayerInputComponent 에서 UEnhancedInputComponent::BindAction(IA, ETriggerEvent::Triggered, ...) 형태로 명시적으로 묶어야 합니다 (아래 의사 코드 참고).

C++ 로 이식 시 형태 (Step 2 미리보기)

C++ · ALsCharacter::SetupPlayerInputComponent (의사 코드) 
void ALsCharacter::SetupPlayerInputComponent(UInputComponent* InputComponent)
{
    if (UEnhancedInputComponent* EIC = Cast<UEnhancedInputComponent>(InputComponent))
    {
        EIC->BindAction(InputConfig->Move,         ETriggerEvent::Triggered, this, &ALsCharacter::OnMove);
        EIC->BindAction(InputConfig->Look,         ETriggerEvent::Triggered, this, &ALsCharacter::OnLook);
        EIC->BindAction(InputConfig->SwitchWeapon, ETriggerEvent::Started,   this, &ALsCharacter::OnSwitchWeapon);
    }
}
★
학습 포인트 헤더에 UInputAction*, UInputMappingContext* 가 등장하므로 Build.cs 의 EnhancedInput 가 Public 의존이어야 함을 떠올려보세요 (섹션 04). 모듈 의존성과 코드 형태가 한 줄로 연결되는 지점입니다.

IMC 의 키 매핑 - 자동 추출의 한계

!
Monolith MCP 는 IMC 의 "키 → IA" 매핑을 emit 하지 않습니다. 본 문서 작성 단계에서 IMC_ALS 의 실제 키 매핑을 Monolith 응답으로 가져올 수 없었기 때문에 본 섹션은 "IA 가 어떤 의미를 가져야 하는지" 까지만 다룹니다. 실제 매핑은 에디터에서 IMC_ALS 를 직접 열어 확인하거나, UE Python 으로 덤프하세요. 자세한 갭 분석은 섹션 09 참조.

확장 시 영향 범위 (예: Fire 입력 추가)

  1. IA 자산 생성 - Content/ALS/Inputs/InputActions/IA_Fire.uasset. Value Type 결정 (Fire 는 Bool).
  2. IMC 매핑 추가 - IMC_ALS 의 매핑 배열에 LeftMouseButton → IA_Fire 추가.
  3. (선택) Trigger/Modifier 설정 - Hold/Tap/Pressed 등.
  4. 핸들러 추가 - BP_LsCharacter EventGraph 에 EnhancedInputAction IA_Fire 노드 배치.
