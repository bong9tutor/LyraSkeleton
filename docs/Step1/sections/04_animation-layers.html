Linked Anim Layer 구조 분석

ABP_Base 의 LinkedAnimLayer(IdleLayer) 슬롯에 무기 상태별 자식 ABP 가 끼워지는 구조. 인터페이스 ALI_Animation 의 함수 한 개(IdleLayer) 를 부모 ABP_Layers 가 구현하고, 자식 ABP_Pistol/ABP_UnArmed 가 상속받는다.

구성 자산 4 종 (실측 기준)

각 카드는 Monolith MCP animation_query.get_abp_info / get_abp_linked_assets 와 blueprint_query.get_functions 의 실측 결과입니다.

ABP_Base 메인 AnimBP
부모AnimInstance implements ALI_Animation

캐릭터 메시의 메인 AnimBP. AnimGraph 에 LinkedAnimLayer(IdleLayer) 슬롯 1 개 + Inertialization + Output Pose.

  • 변수: CurrentWeapon (byte) - 현재 set 되는 노드 없음
  • EventGraph 의 모든 노드 disabled (실 로직 없음)
  • BlueprintThreadSafeUpdateAnimation 그래프 비어있음 (Step 2 채울 영역)
  • GetCharacterMovement() BlueprintPure + PropertyAccess
ABP_Layers 베이스 레이어 부모
부모AnimInstance implements ALI_Animation

ABP_Pistol/UnArmed 의 부모 AnimBP 클래스. 자식들이 공유할 베이스 갱신 슬롯과 인터페이스 구현을 들고 있음.

  • 시퀀스: MM_Unarmed_Idle_Ready (7.57s @ 30fps)
  • 함수 OnIdleUpdate(Context, Node) 비어있음 (Step 2 채울 영역)
  • AnimGraph 가 Output Pose 1 개뿐 (실제 포즈 연결은 아직 없음)
ABP_UnArmed 비무장 자식
부모ABP_Layers 인터페이스부모에서 상속

비무장 상태에서 끼워지는 자식 ABP. EventGraph 의 모든 노드가 disabled - 본질적으로 비어 있음.

  • 자체 시퀀스 없음 (부모의 MM_Unarmed_Idle_Ready 그대로 사용)
  • 총 의존성: 스켈레톤 + 부모 ABP 2 개뿐
ABP_Pistol 권총 자식
부모ABP_Layers 인터페이스부모에서 상속

권총 상태에서 끼워지는 자식 ABP. EventGraph 의 모든 노드가 disabled. 부모와 차이는 자체 시퀀스 1 개를 의존성으로 들고 있다는 점.

  • 시퀀스: MM_Pistol_Idle_ADS (5s @ 30fps, ADS=Aim Down Sights)
  • 실측: get_abp_linked_assets 의 sequences 배열
i
인터페이스 구현 위치 - 흔한 오해 "자식 ABP 가 인터페이스를 직접 구현" 한다고 보기 쉽지만, Monolith 실측으로는 ABP_Pistol/ABP_UnArmed 의 interfaces 배열은 비어 있습니다. 인터페이스는 ABP_Layers 가 한 번 구현하고, 자식 ABP 들은 그것을 상속해 함수만 override 합니다. 결과적으로 슬롯에 끼워 넣을 때는 자식 클래스 (ABP_Pistol_C) 를 인자로 주면 됩니다.
!
현재 프로젝트는 슬롯만 정의된 빈 상태가 많다 ABP_Layers.OnIdleUpdate, ABP_Base.BlueprintThreadSafeUpdateAnimation, ABP_Pistol/UnArmed.EventGraph 모두 노드가 비어 있거나 disabled 상태. 실제 로직 (속도 계산, idle 갱신, ADS 포즈 override 등) 은 향후 채워질 영역. 빈 슬롯 전체 명세는 섹션 05 참조.

Linked Anim Layer 개요

한 AnimBP 의 AnimGraph 안에 슬롯(함수) 을 두고, 슬롯의 실제 구현은 외부 AnimBP 가 채우는 방식. 슬롯의 시그니처는 Animation Layer Interface 자산으로 명시한다. 본 프로젝트에서는 ALI_Animation 이 이 인터페이스이며, 함수는 IdleLayer(): FPoseLink 한 개뿐이다.

개념 흐름 
ALI_Animation (Animation Layer Interface, asset_class = AnimBlueprint)
   │ 슬롯 함수: IdleLayer (단 1 개)
   │   - inputs : 없음
   │   - outputs: IdleLayer (FPoseLink)
   │   # 실측: blueprint_query.get_interface_functions(interface_class=ALI_Animation_C)
   │
   ├── 인터페이스 선언적 구현: ABP_Base   # 자기 AnimGraph 에서 LinkedAnimLayer 노드로 호출
   └── 인터페이스 선언적 구현: ABP_Layers # 자체 시퀀스 MM_Unarmed_Idle_Ready 보유
              ↑ parent_class
       ┌──────┴──────┐
       │             │
ABP_Pistol     ABP_UnArmed   # interfaces=[] 이지만 부모에서 상속
   │             │       # EventGraph 의 모든 노드가 disabled (비어 있음)
   │             └─ depends on: MM_Unarmed_Idle_Ready (부모 ABP_Layers 의 시퀀스)
   └─ depends on: MM_Pistol_Idle_ADS  (자체 시퀀스, ADS = Aim Down Sights)

ABP_Base::AnimGraph (노드 3 개)
   LinkedAnimLayer("ALI_Animation - IdleLayer")
        ↓ Pose
   Inertialization                     # 무기 전환 시 부드러운 블렌딩
        ↓ Pose
   Output Pose

런타임:
   BP_LsCharacter.BeginPlay
     → Mesh->LinkAnimClassLayers(ABP_UnArmed_C)   # 초기 상태
   IA_SwitchWeapon (Axis1D) → Started 발화
     → Truncate → Switch on Int (case 1/2 만)
     → Set EquippedWeapon
     → Mesh->LinkAnimClassLayers(ABP_Pistol_C 또는 ABP_UnArmed_C)

구조적 특성

분기 회피

무기 상태마다 그래프에 Select/Branch 를 추가하지 않는다. 베이스 그래프(ABP_Base) 는 무기 종류가 늘어나도 변경되지 않는다.

작업 격리

무기별 자식 ABP 는 독립 자산이라 다른 무기를 건드리지 않고 수정 가능. 자산 분리로 머지 충돌이 줄어든다.

런타임 비용

상태별로 다른 그래프가 평가되는 것이 아니라, 현재 끼워진 자식 ABP 한 장만 평가된다.

Lyra 호환

Lyra/GASP 의 캐릭터 골격이 동일한 패턴을 사용. 본 프로젝트의 구조를 Lyra 식으로 확장 가능.

런타임 전환 흐름

Sequence 
[유저 입력]
  IA_SwitchWeapon (Axis1D) → Started 핀 발화
       ↓
BP_LsCharacter::EventGraph
  ActionValue(double) → Truncate (KismetMathLibrary.FTrunc) → int
       ↓
  Switch on Int
       ├── case 1: Set EquippedWeapon = UnArmed(NewEnumerator0) → LinkAnimClassLayers(ABP_UnArmed_C)
       ├── case 2: Set EquippedWeapon = Pistol (NewEnumerator1) → LinkAnimClassLayers(ABP_Pistol_C)
       └── (case 0 또는 그 외: 분기 없음, 무시)
       ↓
ABP_Base::AnimGraph 의 LinkedAnimLayer 노드
  새로 끼워진 자식 ABP 의 IdleLayer 함수 평가 → FPoseLink 반환
       ↓
Inertialization 으로 부드럽게 블렌딩
       ↓
  최종 Output Pose
i
왜 case 0 이 없는가? Switch on Int 가 case 1/2 만 다루고 case 0 은 분기가 없습니다. IA_SwitchWeapon 의 ActionValue 는 Axis1D 이므로 입력이 0 일 때도 Started 가 발화될 수 있는데, 그때는 아무 일도 일어나지 않습니다. 즉 입력이 +1 또는 -1 (혹은 +2) 같이 비-0 값일 때만 무기가 전환되는 패턴 (휠 스크롤 한 칸 = 1 단위).
U
주의: UnlinkAnimClassLayers / LinkAnimClassLayers 무기 전환 시 기존 레이어를 해제하고 새 레이어를 거는 함수. LinkAnimGraph(전체 그래프 교체) 와 혼동하지 마세요. Lyra 식 골격은 레이어만 교체합니다.

ABP_Base 의 함수 3 종 (실측)

출처: blueprint_query.get_functions + get_graph_summary.

AnimGraph 그래프
노드 3 개 정상 동작

AnimBP 의 핵심 출력 그래프. LinkedAnimLayer(IdleLayer) 슬롯 1 개에서 받은 포즈를 Inertialization 으로 부드럽게 블렌딩한 뒤 Output Pose 로 내보냄.

  • 슬롯이 정확히 1 개 - 무기 전환 외 다른 분기가 없음
  • Inertialization 덕분에 LinkAnimClassLayers 직후에도 자연스러운 전환
BlueprintThreadSafeUpdateAnimation Override
시그니처(float DeltaTime) 현재 비어있음

AnimInstance 의 스레드세이프 갱신 슬롯. FunctionEntry 노드 1 개뿐이라 실로직은 없음.

  • Step 2 이후 속도/회전/입력 의도 계산을 채울 영역
  • C++ 로 이식하면 NativeThreadSafeUpdateAnimation(float) 으로 대응
GetCharacterMovement BlueprintPure
시그니처() → CharacterMovementComponent PropertyAccess

캐릭터의 무브먼트 컴포넌트를 멀티스레드 안전하게 캐싱하는 헬퍼. PropertyAccess + DynamicCast 패턴.

  • 저자 노트: "PropertyAccess 를 사용하는 이유는 UE5 애니메이션이 멀티 쓰레드(WorkerThread)로 동작하기 때문에 안정성을 위해 사용합니다."
  • 반환 변수명을 반드시 ReturnValue 로 둬야 AccessProperty 노출 (엔진 강제)
★
BP 안에 저자가 직접 남긴 학습 노트 (한국어) GetCharacterMovement 그래프 안의 노드 코멘트는 그대로 인용할 가치가 있습니다. PropertyAccess 패턴의 의도를 한 줄로 정리:
  • PropertyAccess 노드: "PropertyAccess 를 사용하는 이유는 UE5 애니메이션이 멀티 쓰레드(WorkerThread)로 동작하기 때문에 안정성을 위해 사용합니다."
  • FunctionResult 노드: "Outputs 변수명은 반드시 ReturnValue 로 설정 해야 AccessProperty 에 노출 됩니다. (엔진 강제)"
  • 함수 description: "BlueprintPure 설정을 하고, 함수를 래핑 해서, 반환 변수명을 ReturnValue 로 지정하면, 타입이 명확한 오브젝트에서 프로퍼티 를 찾을 수 있게 되어, PropertyAccess 에 변수 노출이 가능하게 됩니다."
ABP_Base::GetCharacterMovement (BlueprintPure, PropertyAccess) 
[FunctionEntry: GetCharacterMovement]
       ↓
[PropertyAccess]                # 멀티 스레드 안전
       ↓ (CharacterOwner.CharacterMovement 형태로 접근)
[DynamicCast → CharacterMovementComponent]
       ├── Success → [FunctionResult] ReturnValue
       └── Fail    → [FunctionResult] ReturnValue (None)

ABP_Base 의 EventGraph (현재 상태)

EventGraph 에는 Event Blueprint Update Animation 과 Try Get Pawn Owner 두 노드만 남아 있으며 모두 disabled. 실 로직 없음.

i
이력 과거에는 SwitchWeapon_1(WeaponType: byte) 커스텀 이벤트가 정의되어 있었고 내부에서 Set CurrentWeapon 만 호출하는 형태였다. 호출처가 없어 미사용 상태였기에 제거되었다. CurrentWeapon 변수 자체는 보존되어 있으며, 향후 BP_LsCharacter 의 EquippedWeapon 과 동기화하는 경로는 PropertyAccess 또는 새 채널로 다시 설계할 영역.

확장 시 영향 범위 (예: Rifle 추가)

  1. E_Weapon 에 Rifle 항목 추가 (현재 항목: UnArmed=0, Pistol=1).
  2. ABP_Rifle 신규 생성. 부모를 ABP_Layers 로 두면 인터페이스 구현은 자동 상속.
  3. BP_LsCharacter 의 Switch on Int 에 새 case 추가, LinkAnimClassLayers(ABP_Rifle_C) 호출.
  4. (선택) IA_Fire 추가 후 IMC_ALS 매핑.

패턴의 핵심: ABP_Base 의 AnimGraph 는 변경되지 않는다.

한계: Monolith MCP 가 자동으로 못 보는 것

!
AnimGraph 의 핀 연결과 State 전이 조건은 MCP 응답에 빠진다. animation_query 는 State 목록과 전이의 토폴로지 만 emit 하고, 전이 룰 그래프 (예: Speed > 50 일 때 Idle → Walk) 는 응답에 없다. AnimGraph 의 의미적 흐름을 문서화할 때는 에디터에서 직접 확인 또는 스크린샷 보조가 필요.
