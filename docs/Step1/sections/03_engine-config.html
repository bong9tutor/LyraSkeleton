엔진 설정과 렌더링 옵션

Config/DefaultEngine.ini 에서 활성화된 렌더링 결정 5 가지(RHI/Lumen/Substrate/RT/AutoExposure) 와 맵·리다이렉트 설정 정리.

설정이 모이는 4 개 파일

파일역할본 섹션에서 다루는 정도
Config/DefaultEngine.ini렌더링 RHI/Lumen/Substrate/RT 등 핵심 결정주역
Config/DefaultGame.ini프로젝트 메타, CommonUI 등한 줄 언급
Config/DefaultInput.ini입력 키 매핑 (현재는 Enhanced Input 가 본진)섹션 07 에서 자세히
Config/DefaultEditor.ini에디터 UI 설정학습용으로 큰 의미 없음

① 그래픽 API와 셰이더 모델 (DX12 + SM6)

DefaultEngine.ini · [/Script/WindowsTargetPlatform.WindowsTargetSettings] 
DefaultGraphicsRHI=DefaultGraphicsRHI_DX12
-D3D12TargetedShaderFormats=PCD3D_SM5
+D3D12TargetedShaderFormats=PCD3D_SM6
-D3D11TargetedShaderFormats=PCD3D_SM5
+D3D11TargetedShaderFormats=PCD3D_SM5
RHI DX12
UE 5 의 신기능(Nanite/Lumen/VSM/Substrate) 은 대부분 DX12 + SM6 환경에서 의도된 동작을 합니다.
SM6 셰이더 모델 6
Wave Intrinsics, 6.x 함수가 필요한 Lumen/Substrate 파이프라인의 전제. SM5 로 내리지 마세요.
i
다른 플랫폼도 SM6. 같은 ini 에 SF_VULKAN_SM6(Linux), SF_METAL_SM6(Mac) 가 함께 켜져 있어 교차 플랫폼 셰이더 풀이 일관됩니다.

② Lumen - 동적 GI + Reflection

DefaultEngine.ini · [/Script/Engine.RendererSettings] 
r.DynamicGlobalIlluminationMethod=1     # 1 = Lumen
r.ReflectionMethod=1                    # 1 = Lumen Reflections
r.GenerateMeshDistanceFields=True       # 메시 거리 필드, Lumen 의 보조
r.Shadow.Virtual.Enable=1               # Virtual Shadow Maps
r.AllowStaticLighting=False             # Lightmass 베이크 사용 안 함

이 다섯 줄이 "이 프로젝트는 정적 라이트맵을 굽지 않고, 모든 GI/그림자를 동적으로 처리한다" 라는 한 줄 정책을 만듭니다. 학습 도중 라이트맵 베이크가 필요한 일은 없습니다.

!
r.AllowStaticLighting=False 의 효과 스태틱 라이트 베이크 옵션이 UI 에서 사라집니다. 라이트맵 UV 가 없는 메시도 그대로 동적 GI 가 들어옵니다. 라이트맵을 굽는 워크플로를 학습하고 싶다면 별도 프로젝트에서 진행하세요.

③ Substrate - 새 머티리얼 셰이딩 모델

DefaultEngine.ini · [/Script/Engine.RendererSettings] 
r.Substrate=True
r.Substrate.ProjectGBufferFormat=0

Substrate 는 UE5 의 새로운 머티리얼 셰이딩 시스템입니다. 기존 Material 노드 그래프는 여전히 사용 가능하지만, Material Editor 의 일부 UI 와 머티리얼 함수의 출력 형태가 달라집니다.

U
왜 켜져 있나 Lyra/ALS 스타일의 캐릭터 셰이딩(피부, 옷 레이어, 헤어) 을 학습 범위로 두기 때문에 Substrate 의 멀티 레이어 표현이 필요합니다.

④ Ray Tracing

DefaultEngine.ini 
r.RayTracing=True
r.RayTracing.RayTracingProxies.ProjectEnabled=True

이 두 줄로 RT 가 프로젝트 전역에서 활성화됩니다. Lumen 자체는 RT 와 SDF(소프트웨어 트레이싱) 를 모두 지원하지만, 둘 다 켜 두면 GPU 가 지원하는 환경에서 Lumen Hardware RT 로 자동 전환됩니다.

↳
RT 가 없는 GPU 라면 Lumen 은 자동으로 SDF 트레이싱(soft path) 으로 떨어집니다. "옵션이 켜져 있다 ≠ 강제된다" 라는 점만 알아두면 됩니다.

⑤ 노출(Exposure) 톤매핑

DefaultEngine.ini 
r.DefaultFeature.AutoExposure.ExtendDefaultLuminanceRange=True
r.DefaultFeature.LocalExposure.HighlightContrastScale=0.8
r.DefaultFeature.LocalExposure.ShadowContrastScale=0.8

Auto Exposure 의 확장 범위와 Local Exposure 의 하이라이트/섀도우 컨트라스트 기본값을 살짝 낮춰 둔 구성입니다. 캐릭터 학습 씬에서 톤이 폭주하지 않게 하기 위한 보수적인 값.

맵 / GameMode 진입점

DefaultEngine.ini · [/Script/EngineSettings.GameMapsSettings] 
GameDefaultMap=/Game/ALS/Maps/L_Start.L_Start
EditorStartupMap=/Game/ALS/Maps/L_Start.L_Start

에디터를 켜면 자동으로 L_Start 가 열리고, PIE 또는 패키지 실행에서도 같은 맵이 첫 화면이 됩니다. 이 맵 안의 World Settings 또는 Project Settings 에서 GameMode 가 BP_LsGameMode 로 지정되어 있습니다.

레거시 호환 - ActiveGameNameRedirects

DefaultEngine.ini · [/Script/Engine.Engine] 
+ActiveGameNameRedirects=(OldGameName="TP_Blank",        NewGameName="/Script/LyraSkeleton")
+ActiveGameNameRedirects=(OldGameName="/Script/TP_Blank",NewGameName="/Script/LyraSkeleton")
!
이 두 줄을 지우면 에셋이 깨집니다. 프로젝트가 과거 TP_Blank 라는 이름으로 만들어졌다가 LyraSkeleton 으로 개명된 이력 때문에, BP/AnimBP 안의 일부 클래스 참조가 TP_Blank 이름으로 직렬화되어 있을 수 있습니다. 이 리다이렉트가 그것을 자동으로 새 이름으로 매핑해 줍니다.
